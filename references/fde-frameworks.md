# FDE核心框架与模型参考

## 反选人哲学：五种"不适合"与五种本质

FDE 不是一个"技术岗"，是一个**用技术做交付的创业者角色**。很多在传统意义上"优秀"的工程师，反而不适合做 FDE——不是他们不够好，是他们的"好"和 FDE 需要的"好"方向不同。

| 不适合的人 | 他们缺的 | FDE 本质 | 真正去处 |
|-----------|---------|---------|---------|
| 完美主义工匠型 | 速度优先于优雅 | **交付力**——在有限时间内产出可用的成果 | 核心产品团队 |
| 坐等需求执行型 | 自己定义问题 | **发现力**——在模糊中识别真正的需求 | 成熟产品团队 |
| 觉得"现在挺好"型 | 对现状的不满 | **洞察力**——看到别人看不到的结构性缺陷 | 稳定运营岗 |
| 只懂技术内向型 | 双向翻译能力 | **翻译力**——在技术和业务之间架桥 | 技术专家路线 |
| 受不了换行业型 | 快速学习元能力 | **适应力**——在任何领域快速找到切入点 | 行业深耕路线 |

**核心悖论**：FDE 最反直觉的地方——你干得越好，越会离开 FDE。因为 FDE 的训练就是创业公司创始人的训练。Palantir 校友创办了 350+ 家科技公司，包括 Anduril（估值超 100 亿美元）、ElevenLabs 等。

### Echo/Delta 倾向自测（Day 1 摸底使用）

| 题目 | 选 A（偏 Echo） | 选 B（偏 Delta） |
|------|----------------|-----------------|
| 看到现有流程的问题 | 难受，想改——"这也太蠢了" | 无所谓——"先搞定再说" |
| 写代码更看重 | 快速跑通——"先让它跑起来" | 结构优雅——"架构不对都是技术债" |
| 和客户沟通更擅长 | 挖掘需求——"你说的不是你真正要的" | 快速搭 Demo——"做个东西给你看" |
| 面对全新行业 | 先找人聊天——"约最懂行的三个人" | 先打开数据——"给我看系统，我自己摸" |
| 核心价值 | 知道问题在哪——"看到结构性缺陷" | 能把方案做出来——"模糊需求也能跑通" |
| 项目结束后 | 总结方法论——"踩过的坑下次不再踩" | 开始新项目——"下一个挑战是什么" |

**结果**：A 多→偏 Echo（洞察力驱动）；B 多→偏 Delta（执行力驱动）；各半→Echo-Delta 复合型（最稀缺，也最容易过载）。

## AI 时代人类五种能力

技术革命三阶段模型中，FDE 处于"技术被商品化、人类稀缺能力重新定价"的关键节点。以下五种能力是 AI 时代人类真正的护城河：

| 能力 | 定义 | FDE 场景 | 为什么 AI 替代不了 |
|------|------|---------|------------------|
| **定义力** | 在混沌中框定真问题的能力 | 客户说"我想用 AI"，FDE 要拆出"你想用 AI 解决什么" | AI 只能回答问题，不能定义问题 |
| **翻译力** | 在技术语言和业务语言之间双向切换 | 把"模型 AUC 0.93"翻译成"停线风险降低 70%" | AI 缺乏对人类组织政治和情绪的理解 |
| **信任力** | 让人愿意把关键决策交给系统 | 6 周内让客户 CIO 从"试试看"到"上线生产" | 信任需要人的在场、承诺和承担 |
| **判断力** | 在信息不完备时做出可逆决策 | 模型两个版本都能跑，选哪个上线？ | AI 可以给概率，但不能替人承担责任 |
| **承责力** | 为结果负最终责任 | "出了问题我来兜"——这句话只有人能说 | 机器无法承担法律和伦理责任 |

**与五横三纵的关系**：五横三纵是"技能层"，五种人类能力是"元认知层"。技能可以被 AI 替代，元认知不能。

## Ontology 本体论：FDE 真正值钱的东西

### 核心问题

数据库存的是"表（Tables）"，人做决策时想的是"实体（Objects）"。这个语义断层是现代企业数据建设的阿喀琉斯之踵。Palantir FDE 花了二十年填上这个断层，武器就是 Ontology。

**朴素定义**：Ontology = 用业务能听懂的话，把数据库里的表重新说一遍。

### Ontology 构建三步法

| 步骤 | 做什么 | 输入 | 输出 | FDE 的角色 |
|------|--------|------|------|-----------|
| 第一步：定义实体（Objects） | 把数据库的表翻译成业务实体 | 表结构 + 业务访谈 | Object 定义（属性+关系） | 在客户现场挖掘"人脑子里想的是什么" |
| 第二步：编织关联（Links） | 把实体之间的关系显性化 | 业务流程 + 数据血缘 | Link 定义（类型+方向+约束） | 发现人凭直觉做的关联，让系统也能做 |
| 第三步：赋予行动（Actions + Write-back） | 让 Ontology 不只是"看"的，还是"做"的 | 操作日志 + 决策记录 | Action 定义 + Write-back 机制 | 把人的决策逻辑编码为系统可执行的动作 |

### Write-back 机制：从"看数据"到"改数据"

传统 BI 是只读的——你只能"看"数据，改不了。Ontology 的 Write-back 机制允许用户在 Ontology 界面直接操作业务实体（比如"把这台设备从产线 A 调到产线 B"），操作会自动写回底层 ERP/MES 系统。

**为什么关键**：没有 Write-back，Ontology 只是一个更好看的 BI 看板；有了 Write-back，Ontology 变成了真正的运营操作系统。这是 Palantir 和传统数据中台的根本区别。

### 案例：Airbus 飞机总装线

Palantir FDE 驻扎在 Hamburg（A350 后段机身组装厂）和 Toulouse（最终组装厂），在嘈杂的、没有标准互联网的工厂车间里写代码。他们把 BOM 表、工位、产线、零件、订单、供应商全部定义为 Object，通过 Link 把"零件→工位→产线→订单→客户"串起来，再用 Action 让调度员可以在界面上一键调整工位分配——这就是 Write-back。结果是 Skywise 平台已有 100+ 家航空公司加入，年营收机会超 8.5 亿美元。

## 五横三纵能力模型

### 五横（五个技能维度）

| 维度 | 核心能力 | 关键指标 |
|------|----------|----------|
| 前沿模型理解力 | 快速阅读最新论文，理解架构图和数学公式 | 一周内将新论文核心思想转化为可运行原型 |
| 生产级软件工程 | 模块化设计、TDD、CI/CD、错误处理、日志系统 | 将研究代码重构为生产代码 |
| 高性能推理优化 | 量化（INT8/FP4）、蒸馏、Triton/TensorRT、KV Cache、推测解码 | 推理成本降5-10倍，质量保持95%+ |
| 云原生基础设施 | K8s、GPU集群管理、自动扩缩容、Istio、边缘部署 | 9-16天完成从代码到生产的全流程 |
| 可观测性与运维 | Prometheus、日志聚合、告警、A/B测试、灰度发布 | 第一天建立完整监控 |

### 三纵（贯穿原则）

- **安全性优先**: 对抗测试 / 数据泄露防护 / 权限控制
- **合规性贯穿**: AI Act / 数据隐私 / 算法透明度
- **可重复性保障**: 模型/数据/配置版本严格对应

## 灰度发布策略

| 阶段 | 流量比例 | 观察时间 | 关注点 | 晋级条件 |
|------|----------|----------|--------|----------|
| Canary | 1% | 1小时 | 系统稳定性（崩溃/内存泄漏/GPU OOM） | 无崩溃，无P0告警 |
| Early Adopters | 5% | 4小时 | 用户反馈（输出质量可接受） | 负面反馈<5% |
| Broad Rollout | 25% | 12小时 | 系统性能（延迟/吞吐量） | P99延迟<阈值 |
| Majority | 50% | 24小时 | 长期稳定性（间歇性问题） | 错误率<0.1% |
| Full Rollout | 100% | 72小时 | 确认全面成功 | 所有指标正常 |

**回滚要求**: 5分钟内将流量回滚到上一个稳定版本。

**部署策略对比**:

| 策略 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 蓝绿部署 | 瞬间切换、回滚快 | 需双倍资源 | 高可用要求 |
| A/B测试 | 可验证价值 | 统计需要样本量 | 新模型效果验证 |
| 影子部署 | 零风险 | 双倍计算成本 | 高风险模型 |
| 灰度发布 | 逐步放量、风险可控 | 时间较长 | **FDE默认推荐** |

## 成本优化矩阵

| 优化策略 | 成本降低 | 质量影响 | 实施难度 | 见效时间 |
|----------|----------|----------|----------|----------|
| 模型量化（INT8） | 40-50% | 微小（<2%） | 低 | 即时 |
| 多模型路由 | 40-60% | 无/正向 | 中 | 1-2周 |
| 批处理优化 | 20-30% | 无 | 低 | 即时 |
| Spot实例 | 60-70% | 无 | 中 | 即时 |
| KV Cache优化 | 20-40% | 无 | 低 | 即时 |
| 边缘部署 | 30-50% | 可能下降 | 高 | 2-4周 |
| 模型蒸馏 | 50-70% | 中等（3-5%） | 高 | 1-2月 |

**黄金法则**: 延迟增加100ms可能导致用户满意度下降20%。优化应在保持用户体验不变的前提下降本。

## AI模型安全风险矩阵

| 安全威胁 | 攻击方式 | 防御策略 |
|----------|----------|----------|
| 模型窃取攻击 | 大量查询API重建参数/训练数据 | 查询频率限制、输出扰动、模型水印 |
| 提示注入攻击 | 精心设计输入让模型执行非预期操作 | 输入过滤、输出验证、沙箱执行 |
| 数据泄露 | 模型输出泄露训练数据中的敏感信息 | PII检测、差分隐私、输出模板化 |
| 对抗样本攻击 | 构造特定输入让模型产生错误输出 | 对抗训练、输入预处理、多模型集成 |
| 供应链安全 | 恶意依赖包、被篡改的模型权重 | 依赖锁定、模型签名验证、SBOM |

## 2026 FDE JD 核心要求分析

基于 OpenAI、Anthropic、Google Cloud、字节跳动、智谱 AI 等公司 2025-2026 年发布的真实 JD，提炼出以下核心趋势。

### T 型能力三支柱（Anthropic JD 明确要求）

| 支柱 | 内容 | 关键词 |
|------|------|--------|
| **核心工程能力（纵深1）** | Python/SQL/云基础架构（AWS/GCP/Azure）、数据管线（Airflow/dbt/Spark）、API集成、SSO/SAML/VPC/IAM/SOC2/HIPAA/FedRAMP | 5-8年产品工程经验，ambiguity下做架构决策 |
| **AI & Agent 专业（纵深2）** | 进阶 Prompt Engineering、LangGraph/LangChain/CrewAI/DSPy、向量数据库/RAG/检索质量调校、模型微调/LoRA/Evals回归、多步骤工具调用链 | LLM 生产经验 + Agent 开发 |
| **策略与沟通（横向）** | High Agency（高自主性）、商业敏感度、顾问气质（discovery访谈/stakeholder mapping）、抗压性 | 6-12周 timebox 内交付可用原型 |

### 2025-2026 JD 关键变化趋势

| 变化 | 具体表现 | 学习者行动 |
|------|---------|-----------|
| **Agentic Engineering 成为硬性要求** | 字节"豆包AI大模型FDE"JD 明确要求 Agentic Engineering：编排、记忆管理、任务交接 | 必须掌握 LangGraph/CrewAI 等框架，会设计多步骤 Agent 工作流 |
| **多模型路由能力** | 客户不再买单"all-in Claude"或"all-in GPT"，FDE 要做成本/延迟/品质的 routing | 练习搭建多模型路由系统，熟悉不同模型的优劣边界 |
| **物理层部署经验** | 能在客户硬件上安装和运行模型，不只会调 API；气隙环境部署（国防/国家实验室） | 掌握 vLLM 本地部署、离线环境模型分发 |
| **Evals First 评估标准** | OpenAI"虎队"模式：成功指标由一线操作者自下而上定义 | 学会设计评估集、建立回归测试 |
| **法规与数据主权意识** | 金管会/PDPA/ISO 27001 多重约束，FDE 必须懂如何把推理放在合规区域 | 了解各行业合规框架，练习私有化部署 |
| **High Agency（高自主性）** | Google JD 原文"创始人心态"——没人写需求文档，需求变了、项目拖了，都是你的 | 培养独立推进项目的能力，不依赖外部资源 |
| **行业深耕 + 快速切换** | 需要"理解产品70%全貌"——不是某个模块专家，什么都得懂一点 | 练习在陌生领域快速建立认知的方法论 |

### 国内外 JD 差异

| 维度 | 硅谷（OpenAI/Anthropic/Google） | 国内（字节/智谱/蚂蚁） |
|------|-------------------------------|---------------------|
| 经验要求 | 5-8年产品工程经验 + LLM 生产经验 | 1-3年即可（入门级岗位更多） |
| 核心技能 | Agent 开发 + 多模型路由 + 气隙部署 | 全栈开发 + LLM API 集成 + 系统架构 |
| 软技能权重 | High Agency + 顾问气质 + 商业翻译 | 项目管理 + 客户沟通 + 交付能力 |
| 薪资 | $350K-$550K（中高阶） | ¥30K-80K/月 |
| 行业偏向 | 金融/国防/制造（纽约为最大 hub） | 互联网/金融/制造（上海为政策推动中心） |

### FDE 不适合应届生

**最关键的一句话**：FDE 不是应届生的岗位。典型背景是两种人：会写代码的产品经理，或有商业嗅觉的工程师。第一年起薪约 $200K+（硅谷），需要 PM/开发经验。

## Palantir Bootcamp 5天极限工作法

| 天 | 做什么 | FDE 在做什么 |
|----|--------|-------------|
| Day 1 | 业务沉浸 | 坐在客户身边，观察真实工作流，问"你现在最头疼什么？" |
| Day 2 | 问题定义 | 把观察到的痛点排序，选出 Top 3 可以 5 天内验证的 |
| Day 3 | 原型搭建 | Delta 快速写代码，Echo 继续深挖需求细节 |
| Day 4 | 迭代验证 | 把原型放到客户面前，看真实反馈，当天改 |
| Day 5 | 客户汇报 | 不是 PPT，是可运行的 Demo + 下一步路线图 |

**关键原则**：
- 第一周交付的代码，大概率会在第二周被推翻重来——客户的理解会随系统运行而进化
- 必须解决 CEO 心中的 Top 5 问题——没有高管支持，内部什么都推不动
- 敢先亏钱——给客户承诺"没效果就退款"，先把信任建立起来
