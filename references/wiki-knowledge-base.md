# FDE Wiki 知识库接入说明

这个文件用于让 `fde-growth-plan` skill 使用 GitHub Wiki 中的 FDE 知识库。

## Wiki 入口

- Wiki 首页：https://github.com/j463853819-dot/fde-growth-plan/wiki
- 知识库首页：https://github.com/j463853819-dot/fde-growth-plan/wiki/FDE知识库
- 阅读路径：https://github.com/j463853819-dot/fde-growth-plan/wiki/00-总览-阅读路径与分类导航

如果仓库内存在 `FDE知识库/`，优先读取本地 Markdown，因为本地文件更适合精确检索和引用。  
如果用户正在 GitHub 上阅读，或当前环境无法读取本地知识库，可以使用 Wiki 链接作为阅读入口。

## 内容定位

Wiki 知识库不是背景资料列表，而是用户成为 FDE 的行动地图。

它覆盖 11 个专题：

1. `01-MVP十二篇`：建立 FDE 基础认知。
2. `02-生产化与交付证据`：理解 Demo、试点、生产和接管之间的门禁。
3. `03-CDEF方法论`：从 Context、Design、Engineer、Feedback 推进项目。
4. `04-Agent与混合作战单元`：理解 Agent、人机协作和 AgentOps。
5. `05-工具链与平台化`：理解 Prompt、RAG、Agent、Eval、Observe 和工程工具链。
6. `06-行业案例库`：用行业场景理解 FDE 落地方式。
7. `07-中国落地与标准`：理解中国市场下岗位、合规、私有化和标准化。
8. `08-商业化与ROI`：判断项目如何证明价值、续费和规模化。
9. `09-职业路径与能力模型`：转型、面试、作品集和能力等级。
10. `10-模板中心`：把方法变成可填写、可交付、可复盘的表格。
11. `11-项目决策与避坑`：判断项目该不该做、是否该做 Agent、什么时候该停。

## Skill 使用方式

### 每日学习

当用户请求每日学习时：

1. 根据用户阶段选择知识库文章。
2. 不要一次性推荐太多链接，通常推荐 1-3 篇。
3. 每次学习都要附一个可完成任务。
4. 如果用户在 GitHub 上阅读，给 Wiki 链接；如果用户在本地仓库使用，给本地文件路径。

### 项目评审

当用户提供项目描述时：

1. 先判断是否适合 FDE。
2. 再判断是否适合 Agent。
3. 根据项目阶段推荐模板。
4. 用知识库中的项目决策文章和模板中心文章生成行动计划。

推荐文章：

- `75-一个需求适不适合用FDE做`
- `76-什么样的AI项目不该做Agent`
- `77-Demo成功后为什么项目还是会失败`
- `79-FDE项目什么时候应该停下来`
- `84-如何判断一个FDE项目已经产生真实价值`

### 生产检查

当用户问 Demo 是否能上线、Agent 是否能进生产、项目是否能交付时：

推荐文章：

- `13-FDE项目为什么需要交付证据包`
- `14-从Demo到生产的三道门禁`
- `17-Agent进入生产前要检查什么`
- `18-评测集回放和回归测试怎么设计`
- `19-SLO告警和值班如何证明系统可接管`
- `20-客户接管清单怎么设计`
- `69-生产准入门禁矩阵模板`
- `73-客户接管清单模板`

### 作品集和面试

当用户希望转型、面试或整理项目经历时：

推荐文章：

- `60-FDE工程师到底需要哪些硬技能`
- `61-不同背景如何转向FDE`
- `62-FDE面试常见问题`
- `63-FDE作品集怎么准备`
- `64-初级中级高级FDE能力差异`

## 链接使用规范

输出给外部用户时，优先给 Wiki 链接，因为它可以直接打开。

输出给本地仓库用户时，优先给本地相对路径，例如：

```text
FDE知识库/11-项目决策与避坑/75-一个需求适不适合用FDE做.md
```

如果链接可能因为中文标题转码失效，可以只给 Wiki 首页和文章标题，让用户通过侧边栏进入。
