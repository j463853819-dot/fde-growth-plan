# 事实约束表和需求切片画布怎么写

FDE 项目早期最容易犯的错误，是把“客户说了什么”直接当成“我们要做什么”。

客户说要 AI 助手，团队就开始做助手；客户说要报表，团队就开始画看板；客户说流程慢，团队就开始自动化。动作很快，但很可能跑偏。

FDE 不能只记录需求，还要记录事实、解释、判断和约束。因为真实项目里，需求往往是客户对问题的初步表达，不是问题本身。

从定义上看，事实约束表是一种现场发现工具，用来把已经观察到的事实、利益相关方的解释、FDE 的判断和不可忽略的约束拆开记录。需求切片画布则是在此基础上，把一个模糊问题切成最小可验证价值闭环。

> **一句可以带走的判断：FDE 不是把客户的话写进需求文档，而是把现场事实整理成可验证的工程切片。**

## 事实、解释、判断为什么要分开

很多项目失败，是因为这三件事混在了一起。

客户说“客服效率低”，这是一种描述。背后可能有事实，也可能有情绪，也可能有管理层的判断。

FDE 需要继续拆：

| 类型 | 示例 | 处理方式 |
| --- | --- | --- |
| 事实 | 过去 30 天退款咨询平均响应 9 分钟 | 可验证、可引用 |
| 解释 | 一线认为慢是因为知识库不好找 | 需要继续求证 |
| 判断 | FDE 判断瓶颈在工单分类和权限查询 | 需要用 Demo 或数据验证 |
| 约束 | 客户订单数据不能出内网 | 影响架构和权限设计 |

这张表的价值，是防止团队把未经验证的解释当成事实，把自己的一厢情愿当成客户需求。

## 约束类型怎么记录

FDE 项目里的约束不是麻烦项，而是方案设计的边界。

常见约束可以分成六类：

| 约束类型 | 要记录的问题 |
| --- | --- |
| 数据约束 | 数据在哪里，质量如何，更新频率是什么 |
| 系统约束 | 能否接接口，是否有遗留系统，是否有性能限制 |
| 权限约束 | 谁能看，谁能改，谁能审批，谁能调用工具 |
| 合规约束 | 是否涉及隐私、审计、留痕、行业监管 |
| 组织约束 | 哪个部门拥有流程，谁是业务 Owner |
| 时间约束 | 试点窗口、上线节点、资源可用性 |

一个看似简单的 AI 助手，可能因为数据不能出域、权限无法细分、业务 Owner 不明确，最后完全不能按原方案推进。早一点记录约束，就是早一点减少返工。

## 事实约束表模板

可以用下面这个轻量模板：

| 字段 | 内容 |
| --- | --- |
| 观察日期 | 事实采集时间 |
| 来源 | 访谈、日志、工单、系统截图、会议纪要 |
| 事实描述 | 尽量写可验证内容 |
| 相关角色 | 谁受影响，谁处理，谁审批 |
| 业务影响 | 时间、成本、错误、风险或体验影响 |
| 解释或假设 | 当前对原因的理解 |
| 约束条件 | 数据、权限、系统、合规、组织、时间 |
| 待验证问题 | 下一步需要验证什么 |

示例：

| 字段 | 内容 |
| --- | --- |
| 事实描述 | 客服处理退款咨询时平均切换 3 个系统 |
| 相关角色 | 一线客服、客服主管、订单系统管理员 |
| 业务影响 | 平均响应时间 8-10 分钟，复杂问题经常升级 |
| 解释或假设 | 知识库和订单数据不在同一工作台 |
| 约束条件 | 订单数据包含敏感信息，只允许授权角色查看 |
| 待验证问题 | 是否可以在客服工作台展示脱敏摘要 |

## 需求切片如何定义

需求切片不是功能点，而是一段能产生业务价值的最小闭环。

一个好的切片至少包含：

- 目标角色。
- 具体场景。
- 输入来源。
- 处理动作。
- 输出结果。
- 验收阈值。
- 不做事项。
- 风险和兜底方式。

比如“做知识库问答”不是好切片，因为它太泛。

更好的切片是：“当客服处理退款咨询时，系统根据订单状态、退款政策和历史相似案例，给出建议回复和引用来源，客服确认后再发送，目标是把平均响应时间从 8 分钟降到 4 分钟以内。”

## 需求切片画布模板

| 模块 | 要写清楚 |
| --- | --- |
| 场景 | 哪个岗位在什么情况下使用 |
| 问题 | 当前卡点和业务损失 |
| 输入 | 数据、文档、系统记录、人工输入 |
| 处理 | AI、规则、流程或人工判断如何协作 |
| 输出 | 用户最终拿到什么结果 |
| 验收 | 用什么指标判断有效 |
| 边界 | 哪些不做，哪些必须人工确认 |
| 风险 | 可能出错在哪里，如何兜底 |
| 下一步 | Demo、试点或停止 |

## 结尾模板

写完事实约束表和需求切片后，可以用四句话做收束：

1. 我们确认的事实是：……
2. 当前最关键的约束是：……
3. 本次优先验证的切片是：……
4. 如果验证成功，下一阶段进入：……

FDE 的早期工作看起来像调研，其实是在为后面的工程判断打地基。

AI 让做东西越来越快，也让做错东西的成本变得更隐蔽。事实约束表和需求切片画布的价值，就是让团队在动手之前，先确认自己没有站在一片误读的地面上。
