# FDE 项目如何定义 ROI

FDE 项目如果不能定义 ROI，就很难获得长期预算。

很多 AI 项目看起来有效，但价值说不清：节省时间算不算钱？减少风险怎么计价？员工体验提升能不能进入 ROI？知识沉淀算不算收益？

从定义上看，ROI，Return on Investment，是投入和回报之间的关系。FDE 项目的 ROI 不只包括直接成本节约，也包括效率提升、风险降低、收入增长、质量改善和组织学习。

> **一句可以带走的判断：FDE 的 ROI 不是上线后才算，而是在场景选择时就要设计。**

## ROI 的四层指标

| 层级 | 示例 |
| --- | --- |
| 使用指标 | 使用人数、任务量、采纳率 |
| 效率指标 | 响应时间、处理时长、人工工时 |
| 业务指标 | 转化率、错误率、成本、收入 |
| 战略指标 | 风险控制、客户体验、知识沉淀 |

只看使用量，很容易高估价值；只看财务结果，又可能低估长期影响。

## 前置基线

算 ROI 前，要先记录基线。

| 基线 | 示例 |
| --- | --- |
| 当前耗时 | 每个工单平均处理 8 分钟 |
| 当前成本 | 每月人工处理成本 30 万 |
| 当前质量 | 错误率 6% |
| 当前体验 | 客户等待时间 12 分钟 |
| 当前风险 | 每月高风险漏判 20 起 |

没有基线，就没有改善。

## ROI 公式不要太复杂

一个简化公式：

```text
ROI =（效率收益 + 收入提升 + 风险减少收益 - 总拥有成本）/ 总拥有成本
```

总拥有成本要包括：

- FDE 人力。
- 模型和平台成本。
- 数据和集成成本。
- 运维和评测成本。
- 客户培训和接管成本。

很多 AI 项目 ROI 失真，是因为只算模型调用成本，不算运营成本。

## 价值证明卡

| 字段 | 内容 |
| --- | --- |
| 场景 | 哪条工作流 |
| 基线 | 当前成本、时间、质量或风险 |
| 改善目标 | 希望改善多少 |
| 评测方法 | 如何收集数据 |
| 成本 | 人力、平台、模型、运维 |
| 结果 | 试点和生产指标 |
| 决策 | 继续、扩大、调整或停止 |

FDE 做 ROI 的目标，不是写一份漂亮报告，而是让客户和团队知道项目是否值得继续投。
