# FDE 项目如何定义 ROI

FDE 项目如果不能定义 ROI，就很难获得长期预算。

这句话听起来像财务要求，但其实是产品问题。

很多 AI 项目看起来有效，却说不清价值：节省时间算不算钱？减少风险怎么计价？员工体验提升能不能进入 ROI？知识沉淀算不算收益？

如果这些问题上线后才开始讨论，通常已经晚了。

> **FDE 的 ROI 不是上线后才算，而是在场景选择时就要设计。**

## 一句话定义

ROI，Return on Investment，是投入和回报之间的关系。

FDE 项目的 ROI 不只包括直接成本节约，也包括效率提升、风险降低、收入增长、质量改善和组织学习。

它不是财务表格最后一行。

它是项目一开始选择场景时就要设计的价值假设：为什么做这条流程，凭什么认为它值得做，做到什么程度应该继续投入。

## ROI 的四层指标

FDE 项目的 ROI 不能只看一个数字。

更合理的做法，是分成四层。

| 层级 | 示例 | 说明 |
| --- | --- | --- |
| 使用指标 | 使用人数、任务量、采纳率 | 证明系统进入流程 |
| 效率指标 | 响应时间、处理时长、人工工时 | 证明工作方式变化 |
| 业务指标 | 转化率、错误率、成本、收入 | 证明业务结果改善 |
| 战略指标 | 风险控制、客户体验、知识沉淀 | 证明长期组织价值 |

只看使用量，很容易高估价值。

只看财务结果，又可能低估长期影响。

比较稳的路径是：先用使用和效率指标证明系统进入流程，再用业务指标证明结果变化，最后再讨论长期战略价值。

## 前置基线

算 ROI 前，要先记录基线。

| 基线 | 示例 |
| --- | --- |
| 当前耗时 | 每个工单平均处理 8 分钟 |
| 当前成本 | 每月人工处理成本 30 万 |
| 当前质量 | 错误率 6% |
| 当前体验 | 客户等待时间 12 分钟 |
| 当前风险 | 每月高风险漏判 20 起 |

没有基线，就没有改善。

很多 AI 项目 ROI 说不清，不是因为没有价值，而是因为项目开始时没有记录“原来是什么样”。

上线以后再补基线，通常会陷入争议：到底是 AI 改善了结果，还是业务波动、人员调整、活动周期造成了变化？

## ROI 公式不要太复杂

一个简化公式就够用：

```text
ROI =（效率收益 + 收入提升 + 风险减少收益 - 总拥有成本）/ 总拥有成本
```

总拥有成本要包括：

- FDE 人力。
- 模型和平台成本。
- 数据和集成成本。
- 运维和评测成本。
- 客户培训和接管成本。

很多 AI 项目 ROI 失真，是因为只算模型调用成本，不算运营成本。

这也是 FDE 必须参与 ROI 定义的原因。只有进过现场的人，才知道系统真正跑起来以后，哪些成本一定会发生。

## 价值证明卡

FDE 可以用一张价值证明卡，把 ROI 前置到项目设计里。

| 字段 | 内容 |
| --- | --- |
| 场景 | 哪条工作流 |
| 基线 | 当前成本、时间、质量或风险 |
| 改善目标 | 希望改善多少 |
| 评测方法 | 如何收集数据 |
| 成本 | 人力、平台、模型、运维 |
| 结果 | 试点和生产指标 |
| 归因说明 | 哪些改善来自项目，哪些可能来自外部因素 |
| 决策 | 继续、扩大、调整或停止 |

FDE 做 ROI 的目标，不是写一份漂亮报告。

而是让客户和团队知道项目是否值得继续投、往哪里扩、什么时候该停。

## 常见误区

| 误区 | 问题 |
| --- | --- |
| 只算节省人力 | 忽略风险、质量和体验 |
| 只算模型成本 | 忽略集成、运维和接管 |
| 没有基线 | 无法证明改善 |
| 指标太远 | 试点周期内看不到结果 |
| 归因太粗 | 无法说明改善来自系统 |
| 只报好消息 | 失去客户对数据的信任 |

ROI 不是为了证明项目一定成功。

ROI 是为了让团队更早知道：这个场景值不值得做，做到什么程度应该继续，什么情况下应该停下来。

## 实战拆解：客服 AI 的 ROI 怎么算

假设一个客服团队每月处理 10 万次咨询。

客户想做客服 AI，最初的说法是：

“希望 AI 能自动回答高频问题，减少客服压力。”

这句话还不能直接算 ROI。

FDE 要先把它拆成可计算的流程。

## 现场发生了什么

调研后发现：

- 每月 10 万次咨询。
- 其中 40% 是高频标准问题。
- 当前平均每次处理 8 分钟。
- 高频问题里，大量时间花在查政策、查订单、组织回复上。
- 复杂投诉、高金额退款必须转人工主管。

这时，ROI 假设可以写得更具体：

> 对高频标准问题，AI 生成建议回复，由客服确认后发送，目标是降低平均处理时长，并保持投诉率不升高。

## FDE 怎么一步步计算

试点后，FDE 发现：

- 高频问题里 60% 可以由 AI 生成建议回复。
- 客服采纳率 70%。
- 被采纳的建议平均节省 3 分钟。

可以先粗算月节省工时：

```text
月节省工时 = 100000 * 40% * 60% * 70% * 3 分钟
```

这不是最终 ROI。

但它把讨论从“AI 有没有用”推进到了“这个场景值不值得继续投”。

接下来要扣掉总拥有成本：

- 模型调用成本。
- 平台订阅成本。
- FDE 和集成成本。
- 评测和运营成本。
- 客户内部维护成本。

还要补充质量和风险指标：

| 指标 | 为什么要看 |
| --- | --- |
| 投诉率 | 防止效率提升带来体验下降 |
| 转人工率 | 判断风险边界是否合理 |
| 修改率 | 判断 AI 建议是否真正可用 |
| 失败样本类型 | 指导下一轮优化 |

## 最后留下了什么

这个项目最后不只留下一个 ROI 数字。

它应该留下：

- 客服退款咨询基线。
- 试点指标和计算口径。
- 采纳率、修改率、转人工率。
- 总拥有成本估算。
- 归因说明。
- 是否扩到物流、售后、会员场景的决策。

这样 ROI 才能真正服务项目决策。

## 可以带走的判断

ROI 不是为了把项目包装得更好看。

ROI 是为了让团队更早知道：这个场景值不值得做，做到什么程度应该继续，什么情况下应该停下来。
