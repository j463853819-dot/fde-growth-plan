# 按效果计费、订阅制和混合定价怎么选

AI 项目定价很容易两头不讨好。

按人天收费，客户觉得你像外包。

按订阅收费，客户担心效果不确定。

按效果收费，供应商又可能背上自己控制不了的风险。

FDE 项目尤其如此。它既有服务成分，又有产品成分，还要进入客户现场。如果定价讲不清楚，项目边界也会跟着讲不清楚。

> **FDE 定价的核心，是把风险、价值和责任分配清楚。**

## 一句话定义

FDE 定价，是把部署服务、平台能力、持续运营和业务结果，组合成双方都能接受的商业模型。

它不应该只按成本定价，也不能只靠愿景定价。

定价本质上是责任结构：

- 谁承担探索风险？
- 谁承担运营责任？
- 谁提供数据和组织配合？
- 谁享受业务收益？
- 什么结果触发续费或增购？

这些问题不说清楚，价格只是一个数字。

## 三种常见模式

| 模式 | 适合阶段 | 优点 | 风险 |
| --- | --- | --- | --- |
| 项目 / 人天 | 早期诊断、PoC、试点部署 | 简单、容易启动 | 容易低毛利，像外包 |
| 订阅制 | 系统稳定运行后 | 收入稳定，可续费 | 需要持续价值证明 |
| 按效果计费 | 指标清楚、归因明确的场景 | 与客户结果绑定 | 指标归因和风险分担难 |

多数 FDE 项目更适合混合模式。

因为 FDE 前期有探索成本，中期有平台能力，后期有运营和效果。

## 混合定价结构

一个更稳的结构通常是四层：

| 层级 | 收费对象 | 解决什么问题 |
| --- | --- | --- |
| 部署费 | Context、Design、Demo、试点、上线 | 覆盖探索和落地成本 |
| 平台订阅 | 模型、工作流、Agent、评测、观测 | 支撑系统持续运行 |
| 运营服务 | 失败样本复盘、评测优化、客户成功 | 让系统持续变好 |
| 效果奖金 | 指标明确后的收益分享 | 绑定结果，但不替代基础收费 |

越早期，越要用部署费保护探索成本。

越稳定，越可以用订阅和效果指标承接持续价值。

## 什么时候适合按效果计费

按效果计费听起来最先进，但不是所有场景都适合。

适合条件：

- 指标清楚。
- 基线可测。
- 归因相对明确。
- 客户能配合流程改变。
- 数据可持续获取。
- 风险边界可控制。

不适合条件：

- 业务结果受太多外部变量影响。
- 客户不愿开放数据。
- 项目还在探索早期。
- 成功标准争议大。
- 供应商无法影响关键流程。

按效果计费不是越高级越好。

如果价值路径还没跑通，所谓“效果计费”最后往往会变成“效果争议”。

## 定价前要问的问题

| 问题 | 目的 |
| --- | --- |
| 价值指标是什么 | 防止卖不清 |
| 客户愿意为哪个结果付费 | 找定价锚点 |
| 供应商承担哪些责任 | 明确边界 |
| 客户需要提供什么条件 | 避免单方背锅 |
| 哪些成本必须单独收费 | 防止 FDE 成本被吞掉 |
| 后续如何续费 | 设计持续收入 |

定价不是财务动作。

它是项目责任结构。

## 常见定价错误

| 错误 | 后果 |
| --- | --- |
| PoC 免费做太深 | 客户习惯免费探索 |
| 订阅不绑定使用价值 | 续费时说不清 |
| 按效果但指标不可控 | 双方争议大 |
| 服务不单独收费 | FDE 成本被吞掉 |
| 没有扩场景价格 | 成功后也无法放大收入 |
| 不写客户配合条件 | 供应商承担不该承担的责任 |

FDE 项目的定价，不能只看“我做了多少工作”。

它要看“我承担了什么责任，创造了什么结果，哪些能力会持续运行”。

## 实战拆解：客服 AI 应该怎么定价

客户想做客服 AI，供应商如果一开始就说“按节省人力分成”，听起来很有吸引力。

但这时风险很高。

因为项目还没有验证：

- 高频问题占比是多少。
- AI 建议采纳率是多少。
- 客服是否愿意用。
- 投诉率会不会上升。
- 数据和权限能否稳定接入。

这时候直接按效果计费，很容易埋下争议。

## 现场发生了什么

客服 AI 的价值路径通常要分阶段跑出来。

第一阶段，FDE 要做现场调研、需求切片、知识库整理、系统集成、评测集和试点上线。

第二阶段，客户开始持续使用 AI 工作流、RAG、Agent、评测和观测能力。

第三阶段，项目才有条件围绕响应时间下降、人工处理量减少、质检效率提升、扩场景数量来设计续费或效果奖金。

## FDE 怎么设计定价

可以设计成三阶段：

| 阶段 | 收费方式 | 定价逻辑 |
| --- | --- | --- |
| 诊断与试点 | 部署费 | 覆盖 FDE 现场勘探、原型、集成、评测和上线成本 |
| 稳定运行 | 平台订阅 | 覆盖模型、工作流、知识库、评测和观测能力 |
| 持续优化 | 运营服务 + 效果奖金 | 围绕指标改善、失败样本复盘和扩场景收费 |

这样客户不会一开始就为不确定结果买单，供应商也不会免费承担所有探索成本。

更重要的是，价格背后的责任边界更清楚。

## 最后留下了什么

一个合格的定价方案，不只是报价单。

它应该包含：

- 每个阶段交付什么。
- 哪些指标用于验收。
- 客户需要提供哪些数据和人员配合。
- 哪些服务包含在订阅里。
- 哪些优化属于额外运营服务。
- 什么条件下触发扩场景或效果奖金。

这些内容写清楚，后面才不容易把 FDE 做成免费兜底。

## 可以带走的判断

FDE 项目定价如果只按人力算，会低估价值。

如果只按效果算，又可能高估可控性。

更成熟的方式，是用部署费覆盖探索，用订阅承接系统能力，用效果指标证明扩张和续费。
