# 按效果计费、订阅制和混合定价怎么选

AI 项目定价很容易两头不讨好。

按人天收费，客户觉得你像外包；按订阅收费，客户又担心效果不确定；按效果收费，供应商可能承担过高风险。FDE 项目尤其如此，因为它既有服务成分，又有产品成分，还要进入客户现场。

从定义上看，FDE 定价是把部署服务、平台能力、持续运营和业务结果组合成可接受的商业模型。它不应该只按成本定价，也不能只靠愿景定价。

> **一句可以带走的判断：FDE 定价的核心，是把风险、价值和责任分配清楚。**

## 三种常见模式

| 模式 | 优点 | 风险 |
| --- | --- | --- |
| 项目/人天 | 简单、容易启动 | 容易低毛利，像外包 |
| 订阅制 | 收入稳定，可续费 | 需要持续价值证明 |
| 按效果计费 | 与客户结果绑定 | 指标归因和风险分担难 |

多数 FDE 项目更适合混合模式。

## 混合定价

一个常见结构：

- 部署费：覆盖 Context、Design、Demo、试点和上线成本。
- 平台订阅：覆盖模型、工作流、Agent、评测和观测。
- 运营服务：覆盖评测、优化、复盘和客户成功。
- 效果奖金：在指标明确时分享收益。

这样既不把所有风险压给客户，也不让供应商免费探索。

## 什么时候适合按效果计费

适合条件：

- 指标清楚。
- 基线可测。
- 归因相对明确。
- 客户能配合流程改变。
- 数据可持续获取。

不适合条件：

- 业务结果受太多外部变量影响。
- 客户不愿开放数据。
- 项目还在探索早期。
- 成功标准争议大。

## 定价前要问

| 问题 | 目的 |
| --- | --- |
| 价值指标是什么 | 防止卖不清 |
| 客户愿意为哪个结果付费 | 找定价锚点 |
| 供应商承担哪些责任 | 明确边界 |
| 客户需要提供什么条件 | 避免单方背锅 |
| 后续如何续费 | 设计持续收入 |

定价不是财务动作，而是项目责任结构。

## 最后的判断

FDE 项目定价如果只按人力算，会低估价值；如果只按效果算，又可能高估可控性。

更成熟的方式，是用部署费覆盖探索，用订阅承接系统能力，用效果指标证明扩张和续费。
