# FDE 面试常见问题

FDE 面试不会只问技术，也不会只问业务。

它更像一次综合判断：你能不能进入陌生现场，能不能定义问题，能不能动手验证，能不能处理生产风险，能不能和客户一起把系统接住。

从定义上看，FDE 面试考察的是候选人在现场发现、工程实现、AI 生产化、客户沟通和结果负责上的综合能力。

> **一句可以带走的判断：FDE 面试真正想看的是你如何在不确定性里推进系统。**

## 技术类问题

| 问题 | 考察点 |
| --- | --- |
| 如何设计一个 RAG 系统？ | 数据、检索、评测、权限 |
| Agent 进入生产前要检查什么？ | 工具权限、trace、接管 |
| 如何排查 AI 回答质量下降？ | 回放、失败样本、根因分析 |
| 如何做私有化部署？ | 环境、依赖、安全、运维 |

回答不要只讲技术名词，要讲生产边界。

## 场景类问题

常见题：

“客户说想做一个 AI 助手，你怎么开始？”

好的回答应该包括：

- 不急着做助手。
- 先确认业务场景。
- 看真实流程和数据。
- 区分事实、解释和判断。
- 切一个价值闭环。
- 做 Demo 验证关键假设。
- 补评测、权限和接管。

## 行为类问题

| 问题 | 面试官想看 |
| --- | --- |
| 讲一次需求不清的项目 | 模糊问题处理能力 |
| 讲一次客户不认可方案 | 沟通和调整能力 |
| 讲一次上线事故 | 责任和复盘能力 |
| 讲一次你拒绝需求 | 边界感 |

FDE 不是客户说什么都做的人。

## 作品集追问

如果你带作品集，面试官可能问：

- 真实问题是什么？
- 你怎么确认不是伪需求？
- 为什么选这个切片？
- Demo 验证了什么？
- 进入生产还差什么？
- 如何评测？
- 谁接管？

一个好作品集，要能经得住这些追问。

## 答题框架

可以用这个结构：

1. 先确认现场和目标。
2. 再拆事实、约束和风险。
3. 切最小价值闭环。
4. 做工程验证。
5. 设计生产门禁。
6. 让客户接管并复盘。

FDE 面试不怕你不知道所有答案，怕的是你只会给一个漂亮方案，却没有推进路径。
