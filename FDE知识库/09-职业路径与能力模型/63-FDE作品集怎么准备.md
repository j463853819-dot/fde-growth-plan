# FDE 作品集怎么准备

FDE 作品集不能只展示页面截图。

因为 FDE 的价值不只是“做出一个东西”，而是从真实问题出发，把它推进成可验证、可运行、可复盘的系统能力。

很多 AI 作品集看起来很完整：有界面，有模型，有演示视频，有 GitHub 仓库。

但面试官追问两句就会发现：真实问题是什么？为什么先做这个切片？怎么评测？进生产还差什么？谁接管？

如果这些答不上来，作品集更像普通 Demo，而不像 FDE 项目。

> **FDE 作品集不是项目陈列，而是一次小型交付证据包。**

## 一句话定义

FDE 作品集，是一组能够证明你具备现场发现、工程验证、生产化思维和复盘沉淀能力的项目材料。

它要让别人相信：

你不是只会做原型，而是知道一个原型怎样走向生产。

## 一个作品集应该包含什么

| 模块 | 内容 | 证明什么 |
| --- | --- | --- |
| 背景 | 为什么做这个项目 | 你不是为了炫技而做 |
| 真实问题 | 你如何确认问题 | 你有现场判断 |
| 价值切片 | 为什么先做这一段 | 你会控制范围 |
| 系统方案 | 数据、流程、AI 和人工如何协同 | 你能设计闭环 |
| Demo | 核心能力如何验证 | 你能动手实现 |
| 评测 | 样本、指标、失败案例 | 你知道怎么判断效果 |
| 生产思考 | 权限、日志、SLO、回滚 | 你知道 Demo 到生产的距离 |
| 复盘 | 学到了什么，哪些可产品化 | 你能沉淀经验 |

如果只有代码仓库，没有问题和证据，作品集会像普通工程项目。

FDE 作品集要多一层“为什么这样做”。

## 适合做什么项目

作品集不需要一开始就做很大的行业系统。

可以从身边真实场景开始：

- 客服问答和工单分流。
- 销售线索摘要。
- 会议纪要到行动项。
- 内容选题雷达。
- 合同条款风险摘要。
- 知识库问答和引用。
- 运营异常监控和原因解释。

关键不是场景宏大，而是闭环完整。

一个小但完整的项目，胜过一个大而空的概念。

## 最小作品集模板

```markdown
项目名称：……

真实问题：
谁在什么流程里遇到什么损失？

现场证据：
你看到了哪些事实，而不是只听到了什么需求？

价值切片：
本项目只验证哪一段闭环？

系统方案：
输入、处理、输出、反馈是什么？

Demo 与评测：
验证了哪些假设？失败样本是什么？

生产化思考：
权限、trace、SLO、回滚和接管怎么设计？

复盘：
哪些经验可以复用？
```

这份模板不追求漂亮。

它追求可追问。

## 作品集的判断标准

| 标准 | 合格表现 |
| --- | --- |
| 真实问题清楚 | 能说明不是伪需求 |
| 价值切片明确 | 不把所有功能塞进第一版 |
| 系统能运行 | 不是纯 PPT 或概念图 |
| 评测可复查 | 有样本、指标和失败案例 |
| 生产边界清楚 | 知道权限、风险、日志和接管 |
| 复盘有沉淀 | 能抽象成模板或下一步能力 |

如果一个作品集失败后，团队仍然不知道下一步该继续、缩小、转向还是停止，说明它还不是一个好的 FDE 作品集。

## 常见误区

| 误区 | 问题 |
| --- | --- |
| 只放截图 | 看不到判断过程 |
| 只讲模型效果 | 看不到业务价值 |
| 没有失败样本 | 看不到评测能力 |
| 没有生产思考 | 像 Demo，不像 FDE |
| 没有复盘 | 看不到成长和抽象能力 |
| 场景太大 | 讲得宏大，但无法验证 |

FDE 作品集不需要假装自己已经做成了一个完整商业产品。

但它必须诚实说明：现在验证了什么，没验证什么，进入生产还差什么。

---

## 实战拆解：一个销售助手作品集怎么写

不要只写：

“我做了一个销售助手，可以生成客户跟进建议。”

这句话太薄了。

它没有说明真实问题，也没有说明为什么这个功能有价值。

## 更好的展开方式

可以这样写：

| 模块 | 示例 |
| --- | --- |
| 真实问题 | 销售不知道哪些线索优先跟进 |
| 现场证据 | CRM 字段不完整，销售靠经验排序 |
| 价值切片 | 新线索进入后生成摘要和优先级建议 |
| 系统方案 | 接 CRM、相似客户、互动记录和销售确认 |
| Demo | 验证销售是否采纳建议 |
| 评测 | 采纳率、修改率、跟进时效 |
| 生产思考 | 权限、日志、推荐解释、人工确认 |
| 复盘 | 线索摘要比话术生成更有价值 |

这样写，面试官看到的不是一个工具。

而是一条完整的 FDE 判断链。

## 作品集可以附哪些材料

| 材料 | 用途 |
| --- | --- |
| 问题定义文档 | 说明项目从哪里来 |
| 需求切片画布 | 说明为什么先做这一段 |
| 架构图 / 流程图 | 说明系统如何运行 |
| 评测样本 | 说明怎么判断效果 |
| 失败样本复盘 | 说明你如何迭代 |
| 接管清单 | 说明上线后谁负责 |
| 项目复盘 | 说明经验如何沉淀 |

这些材料不需要都很长。

但它们要能支撑追问。

## 可以带走的判断

FDE 作品集最重要的不是“我做了什么”。

而是“我如何从真实问题出发，做出判断，并把判断落成系统证据”。
