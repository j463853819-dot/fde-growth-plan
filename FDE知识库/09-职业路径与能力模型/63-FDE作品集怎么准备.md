# FDE 作品集怎么准备

FDE 作品集不能只展示页面截图。

因为 FDE 的价值不只是“做出一个东西”，而是从真实问题出发，把它推进成可验证、可运行、可复盘的系统能力。作品集要展示你的判断链，而不是只展示结果。

从定义上看，FDE 作品集是一组能够证明你具备现场发现、工程验证、生产化思维和复盘沉淀能力的项目材料。

> **一句可以带走的判断：FDE 作品集不是项目陈列，而是一次小型交付证据包。**

## 一个作品集应该包含什么

| 模块 | 内容 |
| --- | --- |
| 背景 | 为什么做这个项目 |
| 真实问题 | 你如何确认问题 |
| 价值切片 | 为什么先做这一段 |
| 系统方案 | 数据、流程、AI 和人工如何协同 |
| Demo | 核心能力如何验证 |
| 评测 | 样本、指标、失败案例 |
| 生产思考 | 权限、日志、SLO、回滚 |
| 复盘 | 学到了什么，哪些可产品化 |

如果只有代码仓库，没有问题和证据，作品集会像普通工程项目。

## 适合做什么项目

可以从身边真实场景开始：

- 客服问答和工单分流。
- 销售线索摘要。
- 会议纪要到行动项。
- 内容选题雷达。
- 合同条款风险摘要。
- 知识库问答和引用。

关键不是场景宏大，而是闭环完整。

## 作品集最小模板

```markdown
项目名称：……

真实问题：
谁在什么流程里遇到什么损失？

现场证据：
你看到了哪些事实，而不是只听到了什么需求？

价值切片：
本项目只验证哪一段闭环？

系统方案：
输入、处理、输出、反馈是什么？

Demo 与评测：
验证了哪些假设？失败样本是什么？

生产化思考：
权限、trace、SLO、回滚和接管怎么设计？

复盘：
哪些经验可以复用？
```

## 常见误区

| 误区 | 问题 |
| --- | --- |
| 只放截图 | 看不到判断过程 |
| 只讲模型效果 | 看不到业务价值 |
| 没有失败样本 | 看不到评测能力 |
| 没有生产思考 | 像 Demo，不像 FDE |
| 没有复盘 | 看不到成长和抽象能力 |

FDE 作品集要让人相信：你不是只会做原型，而是知道一个原型怎样走向生产。
