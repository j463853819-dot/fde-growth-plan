# FDE 工程师到底需要哪些硬技能

FDE 不是只靠“沟通好”就能做的岗位。

它要进入真实客户现场，面对数据、系统、权限、AI、部署和生产责任。软技能很重要，但没有硬技能支撑，FDE 很容易停在咨询或项目协调。

一个更准确的判断是：

FDE 不一定要是团队里最强的单点工程师，但必须知道系统怎样从“能演示”走到“能运行”。

> **FDE 的硬技能不是炫技，而是为了让现场判断能落到系统里。**

## 一句话定义

FDE 的硬技能，是支撑现场问题验证、系统构建、AI 生产化和客户接管的一组工程能力。

它不要求每项都专家级。

但它要求你能把问题推进到可运行系统，并知道系统进入生产前还缺什么。

这也是 FDE 和普通方案角色的区别：你不能只讲“应该怎么做”，还要知道“怎么先跑起来，哪里会坏，谁来接住”。

## 五类硬技能

| 能力 | 具体内容 | 为什么重要 |
| --- | --- | --- |
| 工程基础 | API、数据库、脚本、前后端基础、容器 | 能把想法做成系统 |
| 数据能力 | ETL、数据建模、权限、质量检查 | 能判断数据是否可用 |
| AI 能力 | Prompt、RAG、Agent、评测、回放 | 能把模型放进工作流 |
| 生产能力 | 日志、指标、trace、SLO、告警、回滚 | 能让系统进入真实运行 |
| 交付能力 | ADR、证据包、运行手册、接管清单 | 能让客户接住系统 |

如果只会搭 Demo，还不算完整 FDE。

FDE 的硬技能要覆盖从 Demo 到生产的距离。

## 不同阶段的重点

| 阶段 | 技能重点 | 训练目标 |
| --- | --- | --- |
| 入门 | 能做原型、能接 API、能写清楚问题 | 证明自己能把想法跑起来 |
| 进阶 | 能处理数据、权限、评测和试点 | 证明系统能进入真实流程 |
| 高级 | 能设计生产架构、门禁和接管机制 | 证明客户能长期运行 |

入门阶段不需要什么都会。

但要避免只停在“会用工具”。

工具会变，闭环不会变。能不能定义输入、输出、评测、权限和接管，才是更稳定的能力。

## AI 时代的新硬技能

AI 时代，FDE 还要补一组新的硬技能。

| 技能 | 具体要会什么 |
| --- | --- |
| Agent 状态机 | 能说明 Agent 的状态、工具调用、失败分支和人工接管 |
| 工具权限分级 | 能区分只读、建议、需确认执行、自动执行 |
| Prompt 版本管理 | 能记录版本、变量、适用场景和回滚方式 |
| RAG 评测 | 能设计检索、引用、答案质量和覆盖率评测 |
| 失败样本分析 | 能把线上错误变成优化样本 |
| 成本和延迟监控 | 能解释模型调用成本、响应时间和用户体验 |

这些能力决定 AI 系统能不能进入生产。

一个会写 Prompt 的人，能做出 Demo。

一个懂评测、权限、trace 和回滚的人，才更接近生产级 FDE。

## 关键产物

硬技能不是写在简历上的关键词，而是要能产生产物。

| 产物 | 证明什么 |
| --- | --- |
| 可运行 Demo | 证明你能把想法跑起来 |
| 数据接入说明 | 证明你理解数据来源、权限和质量 |
| 评测集 | 证明你知道如何判断 AI 输出是否可靠 |
| 架构和 ADR | 证明你能解释关键取舍 |
| 日志和监控方案 | 证明你考虑生产运行 |
| 接管清单 | 证明你知道客户如何持续运营 |

FDE 的硬技能，最终都要落在这些证据上。

## 常见误区

| 误区 | 问题 |
| --- | --- |
| 只学 AI 工具 | 能做 Demo，但不懂系统边界 |
| 只补后端技术 | 能写接口，但不懂业务流程 |
| 只会调 Prompt | 遇到数据、权限、评测就卡住 |
| 不懂生产化 | Demo 好看，上线危险 |
| 不写交付证据 | 做了很多事，但客户接不住 |

FDE 的技术学习，要围绕项目闭环组织，而不是围绕工具热度组织。

## 实战拆解：一个客服 AI 助手需要哪些硬技能

假设你要做一个客服 AI 助手。

如果只看表面需求，它像是一个 Prompt 或 RAG 项目：

用户问问题，系统从知识库里找答案，再生成回复。

但 FDE 真正进入现场后，会发现它牵涉一整条生产链路。

## 现场发生了什么

客服处理退款问题时，不只是查 FAQ。

他可能需要同时查看：

- 用户问题。
- 订单状态。
- 退款政策。
- 历史类似工单。
- 高风险投诉规则。
- 当前客服权限。

如果这些信息接不起来，AI 回复再流畅，也只是一个悬空的答案。

## FDE 要处理哪些硬技能

| 工作 | 需要的硬技能 |
| --- | --- |
| 接知识库 | 文档解析、RAG、权限过滤 |
| 接订单系统 | API、身份认证、字段脱敏 |
| 生成回复建议 | Prompt、输出格式、引用来源 |
| 高风险转人工 | 规则、工作流、责任边界 |
| 评测质量 | 样本集、回放、人工标注 |
| 上线运行 | 日志、trace、成本、告警 |
| 客户接管 | 运行手册、失败样本复盘、Owner |

这就是 FDE 的硬技能结构。

它不是为了让你成为所有领域的专家。

而是让你知道每个环节的风险在哪里，能和对应团队一起把系统推到生产。

## 自评表

| 问题 | 如果答不上，需要补 |
| --- | --- |
| 我能否用 API 接两个系统？ | 工程基础 |
| 我能否解释数据权限边界？ | 数据能力 |
| 我能否设计评测集？ | AI 生产化 |
| 我能否看懂日志和 trace？ | 运维能力 |
| 我能否写交付证据包？ | 交付能力 |

## 可以带走的判断

FDE 的硬技能不追求每项完美。

但要能支撑端到端闭环。

你可以有短板，但不能完全看不见生产系统需要什么。
