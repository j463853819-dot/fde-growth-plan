# FDE 工程师到底需要哪些硬技能

FDE 不是只靠“沟通好”就能做的岗位。

它要进入真实客户现场，面对数据、系统、权限、AI、部署和生产责任。软技能很重要，但没有硬技能支撑，FDE 很容易停在咨询或项目协调。

从定义上看，FDE 的硬技能是指支撑现场问题验证、系统构建、AI 生产化和客户接管的一组工程能力。它不要求每项都专家级，但必须能把问题推进到可运行系统。

> **一句可以带走的判断：FDE 的硬技能不是炫技，而是为了让现场判断能落到系统里。**

## 五类硬技能

| 能力 | 具体内容 |
| --- | --- |
| 工程基础 | API、数据库、脚本、前后端基础、容器 |
| 数据能力 | ETL、数据建模、权限、质量检查 |
| AI 能力 | Prompt、RAG、Agent、评测、回放 |
| 生产能力 | 日志、指标、trace、SLO、告警、回滚 |
| 交付能力 | ADR、证据包、运行手册、接管清单 |

如果只会搭 Demo，还不算完整 FDE。

## 不同阶段的重点

| 阶段 | 技能重点 |
| --- | --- |
| 入门 | 能做原型、能接 API、能写清楚问题 |
| 进阶 | 能处理数据、权限、评测和试点 |
| 高级 | 能设计生产架构、门禁和接管机制 |

## AI 时代的新硬技能

AI 时代 FDE 还要补：

- Agent 状态机。
- 工具权限分级。
- Prompt 版本管理。
- RAG 评测。
- 线上失败样本分析。
- 成本和延迟监控。

这些能力决定 AI 系统能不能进入生产。

## 自评表

| 问题 | 如果答不上，需要补 |
| --- | --- |
| 我能否用 API 接两个系统？ | 工程基础 |
| 我能否解释数据权限边界？ | 数据能力 |
| 我能否设计评测集？ | AI 生产化 |
| 我能否看懂日志和 trace？ | 运维能力 |
| 我能否写交付证据包？ | 交付能力 |

FDE 的硬技能不追求每项完美，但要能支撑端到端闭环。
