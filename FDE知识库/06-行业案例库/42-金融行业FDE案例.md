# 金融行业 FDE 案例

金融行业是 FDE 最典型、也最难的场景之一。

它不是没有数字化基础，恰恰相反，金融系统很多、数据很多、流程也很成熟。难点在于合规、权限、审计和风险责任极重，AI 不能只是“看起来聪明”，必须可解释、可追溯、可控制。

从定义上看，金融 FDE 项目通常是把 AI 或数据能力部署到风控、投研、客服、合规、信贷、运营等高约束流程中，并在合规边界内证明效率和风险收益。

> **一句可以带走的判断：金融 FDE 的第一原则不是自动化，而是可控地提升判断效率。**

## 旧流程

以信贷审批辅助为例，旧流程可能是：

- 客户经理收集资料。
- 风控人员查征信、流水、合同和历史记录。
- 多个系统切换。
- 人工写审批意见。
- 合规或上级复核。

效率低，但每一步都有责任边界。

## 现场发现

客户可能说：“我们想做一个信贷审批 Agent。”

FDE 进入现场后可能发现，真实问题不是“自动审批”，而是：

- 材料分散，人工查找耗时。
- 审批意见格式不一致。
- 风险点遗漏依赖个人经验。
- 高风险客户必须人工判断。

第一个切口不应该是全自动审批，而是“风险摘要和证据引用助手”。

## 数据和系统约束

| 约束 | 影响 |
| --- | --- |
| 数据不出域 | 需要私有化或内网部署 |
| 权限分级严格 | 不同角色看到不同字段 |
| 审计要求高 | 每次查询和输出要留痕 |
| 错误成本高 | 高风险场景必须人工确认 |

金融项目里，权限和审计不是后补项，而是方案设计的一部分。

## 方案设计

更稳妥的方案：

- AI 读取授权范围内资料。
- 生成风险摘要和证据引用。
- 给出风险标签，但不直接审批。
- 高风险或低置信度场景转人工。
- 所有输入、检索、输出留 trace。

## 生产门禁

| 阶段 | 门禁 |
| --- | --- |
| Demo | 能否正确引用政策和历史样本 |
| 试点 | 风控人员是否采纳，错误是否可发现 |
| 生产 | 权限、审计、评测、回滚、SLO 完成 |
| 接管 | 风控、IT、安全能共同复查系统 |

## 指标

- 审批材料整理时间下降。
- 风险点遗漏率下降。
- 审批意见一致性提升。
- 人工复核效率提升。
- 越权访问为零。

金融 FDE 的价值，不是让 AI 替代风控，而是让风控拥有更好的证据组织和判断辅助。
