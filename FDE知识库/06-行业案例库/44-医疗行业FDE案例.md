# 医疗行业 FDE 案例

医疗行业的 FDE 必须更克制。

这里的 AI 不能只追求效率，因为每一次建议、摘要和分类都可能影响诊疗、患者隐私和机构责任。

医疗场景不是不能做 AI，而是必须清楚边界：哪些可以辅助，哪些必须由医生确认，哪些绝不能自动化。

> **医疗 FDE 的底线，是 AI 可以减轻负担，但不能模糊责任。**

## 一句话定义

医疗 FDE 项目，是在高度隐私、专业和责任约束下，把 AI 能力部署到病历整理、随访、分诊、科研检索、院内运营等非直接替代诊疗判断的流程中。

它的重点不是“AI 替医生判断”。

而是让医生从重复文书、信息整理和低价值检索中拿回时间。

## 实战拆解：病历摘要辅助

医院提出需求：

“我们想让 AI 自动写病历。”

这句话风险很高。

如果系统直接生成诊断判断，很容易模糊责任边界。FDE 要先把需求拆细：到底是整理历史病历，还是生成随访摘要？是提取检查结果，还是给诊断建议？哪些字段只是事实复述，哪些已经进入临床判断？

更合适的第一个切口是：

> 医生接诊前，系统从授权病历、检查、用药和既往记录中生成摘要草稿，并引用原始来源，由医生确认和修改后进入正式记录。

## 旧流程

以病历摘要辅助为例：

- 医生查看患者历史记录。
- 人工整理主诉、检查、用药和诊疗经过。
- 写入病历或随访记录。
- 上级医生或质控人员复核。

医生时间被大量文书工作消耗，但最终责任仍在医生。

FDE 的方案不能把这个责任偷换给 AI。

## 现场发现

FDE 现场判断后，应该拆出这些问题：

| 问题 | 为什么重要 |
| --- | --- |
| 哪些字段可以自动抽取 | 区分事实和判断 |
| 哪些内容必须医生确认 | 保留责任边界 |
| 哪些表达属于诊断判断 | 不能由 AI 独立生成 |
| 病历质量标准是什么 | 评测需要专家参与 |
| 数据是否允许出院内环境 | 决定部署和权限方案 |

医疗 FDE 的难点，不是“能不能生成”。

是“生成后谁确认，确认前能不能信，确认后如何留痕”。

## 数据和合规约束

| 约束 | 影响 |
| --- | --- |
| 患者隐私 | 数据访问、脱敏和审计必须严格 |
| 医疗责任 | AI 输出必须由医生确认 |
| 术语专业 | 评测需要专家参与 |
| 系统封闭 | HIS、EMR、LIS、PACS 接入复杂 |
| 质控要求 | 输出要符合院内病历规范 |

医疗 FDE 不能用通用互联网产品的节奏推进。

## 方案设计

一个稳妥方案：

- AI 只生成摘要草稿。
- 输出必须引用原始记录。
- 关键诊断字段不自动生成最终结论。
- 医生修改内容回流样本库。
- 高风险场景强制人工确认。
- 每次生成和修改都保留审计记录。

这个方案不追求“替代医生”。

它追求减少医生在信息整理上的重复消耗。

## 生产门禁

| 阶段 | 必须证明 |
| --- | --- |
| Demo | 摘要能正确引用原始资料 |
| 试点 | 医生修改率和节省时间可衡量 |
| 生产 | 隐私、审计、权限、留痕和质控完成 |
| 接管 | 医务、信息、质控和科室共同接管 |

医疗场景里，评测不能只靠通用指标。

必须有专业人员参与样本设计和输出验收。

## 指标

| 指标 | 说明 |
| --- | --- |
| 文书时间 | 医生整理记录时间是否下降 |
| 摘要字段完整率 | 关键事实是否缺漏 |
| 医生修改率 | 草稿是否真正可用 |
| 质控问题 | 是否减少格式或遗漏问题 |
| 越权访问 | 必须为零 |

## 可复用经验

医疗 FDE 可沉淀的能力包括：

- 病历摘要模板。
- 医生确认工作流。
- 专业术语评测集。
- 患者隐私审计机制。
- 高风险内容转人工规则。

医疗 FDE 的价值不是让 AI 站到医生前面。

而是让医生从重复文书和信息整理中拿回时间。

## 可以带走的判断

医疗 FDE 的第一原则，是减轻负担但不转移责任。

如果系统不能说明来源、不能保留医生确认、不能留下审计记录，它就不应该进入医疗生产流程。
