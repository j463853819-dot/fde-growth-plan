# 行业案例应该怎么读

FDE 行业案例最容易被读成“AI 又在哪个行业落地了”。

这样读价值不大。真正有价值的读法，是看同一套 FDE 方法如何在不同行业约束下变形：金融重合规，制造重现场，医疗重风险，政务重责任，零售重规模和速度。

从定义上看，FDE 行业案例不是成功故事，而是一个行业场景中从现场问题、系统约束、价值切口到生产接管的完整路径记录。

> **一句可以带走的判断：读 FDE 案例，不要先看用了什么 AI，而要先看它穿过了哪些现场约束。**

## 案例的十个字段

| 字段 | 要看什么 |
| --- | --- |
| 背景 | 行业为什么需要这个项目 |
| 旧流程 | 原来怎么做，哪里依赖人工 |
| 现场发现 | 真正问题和客户口头需求是否一致 |
| 数据约束 | 数据在哪里，能不能用，谁能看 |
| 系统约束 | 老系统、接口、网络和部署限制 |
| 价值切口 | 第一个小而完整的业务闭环 |
| 方案设计 | AI、规则、人和系统如何协同 |
| 生产路径 | Demo、试点、生产门禁 |
| 结果指标 | 时间、成本、质量、风险或收入变化 |
| 接管方式 | 客户如何运行和继续演进 |

缺少这些字段，案例很容易变成宣传稿。

## 横向比较比单点故事更重要

同一个“客服助手”，在不同行业完全不同。

| 行业 | 关键差异 |
| --- | --- |
| 金融 | 合规、审计、权限、误导风险 |
| 零售 | 高并发、促销节奏、体验一致性 |
| 医疗 | 责任边界、隐私、专业审查 |
| 政务 | 政策口径、信创、流程可追溯 |

FDE 的能力，体现在能识别这些差异，而不是复制同一个模板。

## 案例复盘的关键问题

读完一个案例，至少问：

- 真实问题是什么？
- 旧流程里谁在兜底？
- 第一个价值切片为什么这样选？
- 哪些数据和权限限制决定了方案？
- Demo 到生产经历了哪些门禁？
- 失败样本怎么收集？
- 客户最后接管了什么？
- 哪些经验可以迁移到其他行业？

行业案例真正有用，是因为它能帮下一次项目少踩坑。
