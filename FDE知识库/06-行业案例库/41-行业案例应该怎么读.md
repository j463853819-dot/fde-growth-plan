# 行业案例应该怎么读

FDE 行业案例最容易被读成一句话：

“AI 又在哪个行业落地了。”

这样读价值不大。

真正有价值的读法，是看同一套 FDE 方法如何在不同行业约束下变形：金融重合规，制造重现场，医疗重风险，政务重责任，零售重规模和速度。

> **读 FDE 案例，不要先看用了什么 AI，而要先看它穿过了哪些现场约束。**

## 一句话定义

FDE 行业案例不是成功故事，而是一个行业场景中从现场问题、系统约束、价值切口到生产接管的完整路径记录。

它应该能帮读者训练迁移能力：下次进入相似行业时，知道先看什么、先避开什么、先验证什么。

## 案例的十个字段

一个可用的 FDE 行业案例，至少要包含十个字段：

| 字段 | 要看什么 |
| --- | --- |
| 背景 | 行业为什么需要这个项目 |
| 旧流程 | 原来怎么做，哪里依赖人工 |
| 现场发现 | 真正问题和客户口头需求是否一致 |
| 数据约束 | 数据在哪里，能不能用，谁能看 |
| 系统约束 | 老系统、接口、网络和部署限制 |
| 价值切口 | 第一个小而完整的业务闭环 |
| 方案设计 | AI、规则、人和系统如何协同 |
| 生产路径 | Demo、试点、生产门禁 |
| 结果指标 | 时间、成本、质量、风险或收入变化 |
| 接管方式 | 客户如何运行和继续演进 |

缺少这些字段，案例很容易变成宣传稿。

宣传稿让人兴奋。

案例让人下次少踩坑。

## 横向比较比单点故事更重要

同一个“客服助手”，在不同行业完全不同。

| 行业 | 关键差异 | FDE 重点 |
| --- | --- | --- |
| 金融 | 合规、审计、权限、误导风险 | 可控地提升判断效率 |
| 零售 | 高并发、促销节奏、体验一致性 | 快速闭环和规模运营 |
| 医疗 | 责任边界、隐私、专业审查 | 辅助医生，不模糊责任 |
| 政务 | 政策口径、信创、流程可追溯 | 公共责任链和可解释 |
| 制造 | 现场设备、隐性经验、停线成本 | 把经验和异常处理结构化 |

FDE 的能力，体现在能识别这些差异，而不是复制同一个模板。

## 案例复盘的关键问题

读完一个案例，至少问：

- 真实问题是什么？
- 旧流程里谁在兜底？
- 第一个价值切片为什么这样选？
- 哪些数据和权限限制决定了方案？
- Demo 到生产经历了哪些门禁？
- 失败样本怎么收集？
- 客户最后接管了什么？
- 哪些经验可以迁移到其他行业？

## 实战拆解：为什么“智能客服”不是一个案例

“某企业上线智能客服，响应效率提升”不是 FDE 案例。

它太粗了。

一个可用案例应该继续拆：

| 问题 | 要补充的信息 |
| --- | --- |
| 客服处理什么问题 | 售前咨询、售后退款、投诉、内部 IT 支持完全不同 |
| AI 进入哪个环节 | 分流、检索、回复草稿、工单创建、质检复盘 |
| 哪些问题不能自动化 | 投诉、赔付、高金额、合同、隐私 |
| 怎么证明有效 | 响应时间、采纳率、转人工准确率、投诉率 |
| 谁接管系统 | 客服主管、运营、IT、安全、产品团队 |

只有补到这个颗粒度，行业案例才有迁移价值。

## 可以带走的判断

行业案例真正有用，不是因为它讲了一个成功故事。

而是因为它把成功背后的现场约束、工程取舍和接管机制讲清楚。

FDE 读案例，读的不是热闹。

读的是下一个项目的判断力。
