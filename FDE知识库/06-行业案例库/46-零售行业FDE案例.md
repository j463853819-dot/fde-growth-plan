# 零售行业 FDE 案例

零售行业的 FDE 特点，是速度快、场景多、反馈密。

门店、客服、会员、商品、供应链、促销、内容运营都可能成为 AI 工作流切入点。相比金融和医疗，零售的单点风险可能低一些，但规模、波动和体验一致性要求很高。

从定义上看，零售 FDE 项目是把 AI 能力部署到人货场相关流程中，通过更快的信息处理、更准的推荐、更稳定的客服和更及时的运营反馈提升业务效率。

> **一句可以带走的判断：零售 FDE 的关键，是在高频变化里找到能快速闭环的价值切口。**

## 旧流程

以电商客服分流为例：

- 用户咨询进入客服系统。
- 人工判断问题类型。
- 简单问题手动回复。
- 复杂问题转售后或运营。
- 高频问题靠人工总结。

大促期间，问题量激增，人工分流和回复压力很大。

## 现场发现

客户可能说：“我们想做智能客服。”

FDE 进入现场后会继续拆：

- 哪类问题最高频？
- 哪些能标准回复？
- 哪些必须查询订单？
- 哪些涉及投诉和赔付？
- 大促期间知识库如何更新？

第一个切口可以是“高频售后问题分流和建议回复”。

## 数据和系统约束

| 约束 | 影响 |
| --- | --- |
| 订单数据实时变化 | 需要稳定接口和权限 |
| 知识库更新频繁 | Prompt 和知识版本要管理 |
| 高峰流量明显 | 要关注延迟和成本 |
| 体验一致性 | 输出语气和政策口径要统一 |

## 方案设计

可行方案：

- AI 先分类咨询类型。
- 高频低风险问题生成建议回复。
- 涉及赔付、投诉、高金额订单转人工。
- 收集客服修改内容。
- 每日复盘新增问题类型。

## 指标

- 首响时间下降。
- 简单问题自动分流率提升。
- 人工修改率下降。
- 投诉场景转人工准确率提升。
- 大促期间成本和延迟可控。

## 接管方式

零售项目接管要让运营和客服团队参与：

- 客服主管负责反馈失败样本。
- 运营负责更新活动政策。
- IT 负责接口和权限。
- FDE/产品团队负责把高频模板沉淀成平台能力。

零售 FDE 的优势在于反馈快。只要设计好评测和回放，系统能很快从真实使用中学习。
