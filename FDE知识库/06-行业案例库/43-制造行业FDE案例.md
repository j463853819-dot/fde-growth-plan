# 制造行业 FDE 案例

制造行业的 FDE，第一步往往不是进会议室，而是进车间。

很多制造企业并不缺系统：ERP、MES、SCADA、WMS、设备台账、质检系统都有。但 IT 系统和现场作业之间经常断裂，一线人员仍然靠经验、纸单、微信群和老师傅判断。

> **制造 FDE 的关键，不是把 AI 带进工厂，而是先尊重工厂里已经存在的隐性知识。**

## 一句话定义

制造 FDE 项目，是把 AI、数据和自动化能力嵌入生产、设备、质量、供应链等现场流程中，让经验型判断逐步变成可记录、可复查、可优化的系统能力。

这类项目不能只坐在办公室设计。

必须回到设备、产线、班组、维修和质检现场。

## 实战拆解：设备异常归因助手

一家制造企业提出需求：

“我们想做设备故障诊断 AI。”

这句话听起来很合理。设备报警多，维修记录多，老师傅经验宝贵，AI 好像可以直接诊断。

但 FDE 进车间后，往往会发现更真实的问题：

设备异常不是单纯“诊断不出来”，而是设备日志、质检结果、维修工单和排产计划对不上。主管每天花很多时间，不是在分析异常，而是在确认这个异常到底归谁处理。

所以第一个切口不是“AI 自动诊断故障”。

而是：

> 当设备报警后，系统能否对齐报警日志、质检记录、维修工单和历史相似案例，形成一个可追踪的异常事实包，帮助维修人员判断可能原因和下一步动作？

## 旧流程

以设备故障诊断为例：

- 设备报警。
- 一线操作员初步判断。
- 维修人员查历史记录。
- 老师傅根据经验判断原因。
- 维修后口头复盘，知识很少沉淀。

很多关键经验不在系统里，而在人脑里。

这就是制造 FDE 的入口。

## 现场发现

FDE 现场观察后可能发现：

| 发现 | 影响 |
| --- | --- |
| 设备日志不完整 | 模型无法直接可靠诊断 |
| 维修记录字段不统一 | 历史案例难以召回 |
| 故障原因描述口语化 | 需要先标准化分类 |
| 老师傅经验没有结构化 | AI 缺少高质量知识来源 |
| 生产线不能随便停机测试 | 试点必须低风险 |

第一个切口可以是“设备报警后的相似案例推荐和维修建议草稿”。

AI 不直接控制设备，只做诊断辅助和知识沉淀。

## 数据和系统约束

| 约束 | 影响 |
| --- | --- |
| OT 系统封闭 | 数据接入要谨慎 |
| 停线成本高 | 试点必须低风险 |
| 记录质量差 | 需要先做数据清洗和标准化 |
| 现场网络复杂 | 部署和同步方式要适配 |
| 班组习惯强 | 系统必须贴近现场动作 |

制造业项目不能把“系统里有数据”误当成“数据可用”。

## 方案设计

一个可行方案：

- 先接入历史维修记录和报警日志。
- 标准化故障类型和处理动作。
- 建立相似案例检索。
- 输出可能原因、参考案例和建议检查项。
- 让维修人员确认建议是否有用。
- 收集修改和补充，形成经验库。

这个方案的核心不是“AI 预测一切”。

而是让每次异常处理都能沉淀成下一次可复用的现场知识。

## 生产路径

| 阶段 | 重点 |
| --- | --- |
| Demo | 用历史故障样本验证相似案例推荐 |
| 试点 | 在一条产线或一类设备上使用 |
| 生产 | 接入权限、日志、告警和人工确认 |
| 接管 | 设备、IT、生产管理共同维护知识库 |

试点最好从低风险、频率高、数据相对完整的设备类型开始。

不要一开始碰最关键产线的自动控制。

## 指标

| 指标 | 说明 |
| --- | --- |
| 故障定位时间 | 从报警到初步原因判断的时间 |
| 相似案例采纳率 | 维修人员是否认可推荐 |
| 复发故障比例 | 同类问题是否减少 |
| 维修记录完整率 | 经验是否被结构化沉淀 |
| 停线影响 | 不能因为试点扩大生产风险 |

## 可复用经验

制造 FDE 最重要的资产，往往不是模型，而是：

- 设备对象模型。
- 故障分类体系。
- 维修动作模板。
- 现场经验结构化方法。
- IT/OT 数据接入边界。
- 班组反馈和复盘机制。

制造业的宏大叙事不是“AI 改造工厂”。

而是让那些长期藏在现场的人类经验，终于有机会变成组织能力。

## 可以带走的判断

制造 FDE 的价值，不是让 AI 一步到位地诊断所有故障。

是把报警、维修、质检和老师傅经验连成可复查的事实链，让每一次异常处理都能沉淀成下一次更快的判断。
