# 制造行业 FDE 案例

制造行业的 FDE，第一步往往不是进会议室，而是进车间。

很多制造企业并不缺系统：ERP、MES、SCADA、WMS、设备台账、质检系统都有。但 IT 系统和现场作业之间经常断裂，一线人员仍然靠经验、纸单、微信群和老师傅判断。

从定义上看，制造 FDE 项目是把 AI、数据和自动化能力嵌入生产、设备、质量、供应链等现场流程中，让经验型判断逐步变成可记录、可复查、可优化的系统能力。

> **一句可以带走的判断：制造 FDE 的关键，不是把 AI 带进工厂，而是先尊重工厂里已经存在的隐性知识。**

## 旧流程

以设备故障诊断为例：

- 设备报警。
- 一线操作员初步判断。
- 维修人员查历史记录。
- 老师傅根据经验判断原因。
- 维修后口头复盘，知识很少沉淀。

很多关键经验不在系统里，而在人脑里。

## 现场发现

客户可能说：“我们想做设备故障诊断 AI。”

FDE 现场观察后可能发现：

- 设备日志不完整。
- 维修记录字段不统一。
- 故障原因描述很口语化。
- 老师傅经验没有结构化。
- 生产线不能随便停机测试。

第一个切口可以是“设备报警后的相似案例推荐和维修建议草稿”。

## 数据和系统约束

| 约束 | 影响 |
| --- | --- |
| OT 系统封闭 | 数据接入要谨慎 |
| 停线成本高 | 试点必须低风险 |
| 记录质量差 | 需要先做数据清洗和标准化 |
| 现场网络复杂 | 部署和同步方式要适配 |

制造业项目不能只坐在办公室设计。

## 方案设计

一个可行方案：

- 先接入历史维修记录和报警日志。
- 标准化故障类型和处理动作。
- 建立相似案例检索。
- 让维修人员确认建议是否有用。
- 收集修改和补充，形成经验库。

AI 不直接控制设备，只做诊断辅助和知识沉淀。

## 生产路径

| 阶段 | 重点 |
| --- | --- |
| Demo | 用历史故障样本验证相似案例推荐 |
| 试点 | 在一条产线或一类设备上使用 |
| 生产 | 接入权限、日志、告警和人工确认 |
| 接管 | 设备、IT、生产管理共同维护知识库 |

## 可复用经验

制造 FDE 最重要的资产，往往不是模型，而是：

- 设备对象模型。
- 故障分类体系。
- 维修动作模板。
- 现场经验结构化方法。
- IT/OT 数据接入边界。

制造业的宏大叙事不是“AI 改造工厂”，而是让那些长期藏在现场的人类经验，终于有机会变成组织能力。
