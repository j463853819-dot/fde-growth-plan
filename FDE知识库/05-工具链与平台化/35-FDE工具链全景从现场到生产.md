# FDE 工具链全景：从现场到生产

很多团队做 AI 项目，最开始选工具时问的是：

“哪个平台最快？”

这个问题不能说错，但太早了。

因为一个工具在 Demo 阶段很顺，不代表它能支撑试点；能支撑试点，也不代表它能进入生产。真正适合 FDE 的工具链，要覆盖从现场发现到客户接管的完整路径。

> **FDE 选工具，不是选最强平台，而是选能把项目从现场带到生产的组合。**

## 一句话定义

从定义上看，FDE 工具链是一组围绕现场勘探、需求切片、原型构建、AI/Agent 编排、评测回放、可观测性、发布运维和交付证据的工具组合。它不是单一平台，而是一套工作系统。

## 六个阶段

| 阶段 | 典型工具能力 |
| --- | --- |
| Plan | 访谈整理、流程图、事实约束表、需求切片 |
| Build | Prompt、RAG、Agent、低代码原型、代码生成 |
| Eval | 评测集、回放、人工评审、失败样本管理 |
| Deploy | API 服务、容器、权限、灰度、配置管理 |
| Observe | 日志、指标、trace、成本、用户反馈 |
| Handover | 证据包、运行手册、接管清单、复盘材料 |

很多团队只重视 Build，所以 Demo 很快；但忽略 Eval、Observe 和 Handover，所以生产很慢。

## 每个阶段最容易缺什么

FDE 选工具时，不只是看“这个阶段有什么工具”，还要看“这个阶段最容易漏什么”。

| 阶段 | 最容易漏掉 | 后果 |
| --- | --- | --- |
| Plan | 事实和假设没有分开 | Demo 验证错问题 |
| Build | 临时数据和临时权限没记录 | 原型冒充生产能力 |
| Eval | 没有失败样本和回放 | 效果只能靠体感判断 |
| Deploy | 没有灰度和回滚 | 上线风险一次性放大 |
| Observe | 只看服务可用，不看输出质量 | AI 变差后没人发现 |
| Handover | 没有 Owner 和运行手册 | 客户无法接管 |

这张表是工具链选型的底层逻辑。

FDE 不是为了把工具堆满，而是为了让每个阶段的关键风险有人接住。

## 工具链的三层结构

| 层级 | 作用 |
| --- | --- |
| 前台工具 | 帮 FDE 和业务方快速看见原型 |
| 中台能力 | 管理 Prompt、知识库、Agent、工作流和评测 |
| 后台工程 | 部署、监控、权限、日志、CI/CD 和回滚 |

如果只有前台工具，项目容易停在演示；如果只有后台工程，项目又会变得太重。FDE 要在速度和可控之间做组合。

## 选型时先问五个问题

1. 这个工具解决 FDE 哪个阶段的问题？
2. 它能否导出或沉淀交付证据？
3. 它是否支持权限、审计、版本和回滚？
4. 它能否和客户现有系统集成？
5. 它是否方便客户后续接管？

工具不是越多越好。没有边界的工具链，会让项目碎片化。

## 工具链不是采购清单，而是交付链

一个成熟 FDE 团队看工具，不会只看功能列表。

它会看这件工具能不能进入交付链：

| 交付问题 | 工具需要支持 |
| --- | --- |
| 如何证明场景真实 | 访谈、样本、流程、事实记录 |
| 如何证明系统有效 | Eval、回放、人工验收 |
| 如何证明系统稳定 | 日志、指标、trace、告警 |
| 如何证明系统可控 | 权限、审计、灰度、回滚 |
| 如何证明客户能接管 | 手册、Owner、版本和变更记录 |

如果一个工具只能帮你把 Demo 做得更快，却不能留下这些证据，它就只是原型工具。

原型工具当然有价值。

但 FDE 不能把原型工具误当成交付体系。

## 最小组合

一个轻量 FDE 工具组合可以是：

| 任务 | 工具类型 |
| --- | --- |
| 现场发现 | 文档、表格、白板、录音转写 |
| 原型构建 | Agent/RAG 平台、代码助手 |
| 评测回放 | Eval 工具、样本库、人工标注表 |
| 观测运行 | 日志、trace、成本监控 |
| 交付证据 | 知识库、ADR、接管清单 |

FDE 工具链的终极标准，不是让 FDE 看起来更忙，而是让现场学习更快沉淀、让系统更容易进入生产。

## 实战拆解：为什么 Demo 很快，生产很慢

一个客服 AI 助手项目，团队用低代码平台两天就搭出了 Demo。

知识库能接，回复能生成，页面也能展示。业务负责人一看很满意。

但项目往前走时，立刻遇到另一组问题：

- 评测样本放哪里管？
- Prompt 改了怎么回放？
- 订单系统权限谁控制？
- 日志、trace、成本怎么观测？
- 客户以后接手，靠哪个工具看运行状态？

这时候你会发现，真正的 FDE 工具链从来不只是“搭得快”的那一层。

它至少要同时覆盖：

| 阶段 | 需要的工具能力 |
| --- | --- |
| 现场发现 | 访谈整理、事实约束表、切片画布 |
| 原型构建 | Prompt、RAG、Agent、低代码或代码平台 |
| 质量控制 | 评测集、回放、失败样本管理 |
| 生产运维 | 部署、权限、日志、trace、告警、回滚 |
| 客户接管 | 证据包、运行手册、接管清单 |

所以工具链真正难的地方，不是“选哪个单点工具”。

而是能不能把这些阶段接成一条连续交付链。

## 可以带走的判断

工具链的本质，是把 FDE 项目从“个人能力”变成“组织能力”。

个人强，可以把 Demo 做出来。

工具链成熟，才能让团队反复把现场问题推进到生产系统。
