# 从原型到生产的工程化工具链

原型工具解决“能不能看见”，工程化工具链解决“能不能依赖”。

FDE 项目最常见的断裂，是 Demo 用一套轻量工具做得很快，但进入试点和生产后，权限、部署、监控、评测、回滚都没有准备好。

从定义上看，工程化工具链是把 AI 原型转成可部署、可测试、可观测、可回滚、可接管系统的一组工程能力。它包括代码管理、环境管理、服务化、容器化、CI/CD、监控告警、评测回放和运行手册。

> **一句可以带走的判断：原型证明想法，工程化证明系统能承受真实世界。**

## 原型阶段需要什么

原型阶段工具要轻。

| 能力 | 目标 |
| --- | --- |
| 快速页面 | 让业务方看到流程 |
| 简单数据接入 | 验证输入是否可用 |
| Prompt/RAG 原型 | 验证输出是否有价值 |
| 手工评测 | 快速暴露错误 |

原型阶段可以手工，但必须记录哪些是临时方案。

## 试点阶段需要什么

试点开始后，工具链要补证据。

| 能力 | 目标 |
| --- | --- |
| 版本管理 | 知道每次改了什么 |
| 评测回放 | 确认变更没有破坏旧能力 |
| 权限控制 | 限制真实数据和工具调用 |
| 日志 trace | 能定位失败路径 |
| 用户反馈 | 收集线上失败样本 |

试点不是为了证明完美，而是为了安全暴露问题。

## 生产阶段需要什么

生产阶段要补运行和接管。

| 能力 | 目标 |
| --- | --- |
| API 服务化 | 稳定接入业务系统 |
| 容器和环境管理 | 保证部署可复现 |
| CI/CD | 规范发布和回滚 |
| SLO 和告警 | 让客户看懂系统状态 |
| 运行手册 | 让客户团队能接管 |

生产工程化不等于把系统做重，而是把风险变得可见、可控。

## 一个渐进路径

| 阶段 | 工具策略 |
| --- | --- |
| Demo | 低代码平台、脚本、轻量知识库 |
| 试点 | 增加版本、评测、日志、权限 |
| 生产初版 | 服务化、容器化、监控、回滚 |
| 规模化 | 多租户、模板化、自动化运营 |

FDE 不需要一开始就上最重架构，但必须知道什么时候该补哪块能力。

## 上生产前的工程检查

- 是否有代码和配置版本？
- 是否有环境变量和密钥管理？
- 是否有评测集和回放报告？
- 是否有日志、指标和 trace？
- 是否有灰度和回滚？
- 是否有运行手册和 Owner？

工程化工具链的目标，不是让技术显得专业，而是让业务有理由信任系统。
