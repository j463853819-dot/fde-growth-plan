# RAG、Agent、Eval、Observe 分别需要什么工具

FDE 做企业 AI 项目时，经常会同时听到四个词：RAG、Agent、Eval、Observe。

它们经常被混在一起，但解决的问题完全不同。

RAG 解决知识和数据如何进入模型，Agent 解决模型如何调用工具执行任务，Eval 解决质量如何判断，Observe 解决系统运行后如何被看见。

> **RAG 让 AI 有知识，Agent 让 AI 有动作，Eval 让 AI 有标准，Observe 让 AI 有责任。**

## 一句话定义

RAG、Agent、Eval、Observe 构成企业 AI 生产化的基本控制面。

少了任何一类，项目都容易停在 Demo。

| 能力 | 解决的问题 | 缺失后果 |
| --- | --- | --- |
| RAG | AI 引用什么知识 | 回答没有证据或知识过期 |
| Agent | AI 能做什么动作 | 停在问答，进不了流程 |
| Eval | AI 做得对不对 | 只能靠感觉判断 |
| Observe | AI 运行得怎么样 | 出错后看不见、接不住 |

## RAG 需要什么工具

RAG 工具要解决知识处理问题。

| 能力 | 说明 | FDE 要检查什么 |
| --- | --- | --- |
| 文档解析 | 处理 PDF、Word、网页、表格 | 是否保留来源和更新时间 |
| 切分和清洗 | 让知识块可检索 | 切分是否破坏业务语义 |
| 向量库 | 存储和召回知识 | 是否支持权限过滤 |
| Rerank | 提高检索相关性 | 是否能解释召回结果 |
| 引用溯源 | 让答案有证据 | 用户是否能看到来源 |

FDE 做 RAG 时，最怕只追求“能回答”。

真正要看的是：知识来源是否可信，权限是否正确，更新机制是否稳定，回答是否能引用证据。

## Agent 需要什么工具

Agent 工具要解决行动问题。

| 能力 | 说明 | FDE 要检查什么 |
| --- | --- | --- |
| 工具注册 | 定义 Agent 可调用能力 | 工具描述是否清楚 |
| 权限分级 | 控制只读、建议、写入 | 是否有高风险审批 |
| 状态管理 | 管理计划、执行、观察、重试 | 是否能终止和降级 |
| 审批节点 | 高风险动作人工确认 | 谁确认，如何留痕 |
| 执行 trace | 回放每一步动作 | 出错后能否定位 |

Agent 的工具层越强，越要小心权限边界。

一个会写入系统的 Agent，本质上已经进入业务责任链。

## Eval 需要什么工具

Eval 工具要解决质量问题。

| 能力 | 说明 | FDE 要检查什么 |
| --- | --- | --- |
| 样本管理 | 正例、反例、边界样本 | 是否来自真实任务 |
| 自动评测 | 格式、引用、准确性、拒答 | 标准是否具体 |
| 人工标注 | 专家判断和业务验收 | 谁有最终判断权 |
| 回放测试 | 变更后复查旧样本 | 是否接入上线门禁 |
| 失败分析 | 聚类和根因标注 | 能否进入下一轮改进 |

没有 Eval，AI 项目只能靠感觉迭代。

靠感觉迭代的系统，很难进入生产。

## Observe 需要什么工具

Observe 工具要解决运行问题。

| 能力 | 说明 | FDE 要检查什么 |
| --- | --- | --- |
| 日志 | 记录事件 | 是否能定位单次任务 |
| 指标 | 看成功率、延迟、成本 | 是否能连接业务指标 |
| Trace | 看请求链路 | 是否覆盖检索、模型和工具调用 |
| 告警 | 异常时通知 Owner | 是否有响应动作 |
| 反馈 | 收集用户修改和失败样本 | 是否回流 Eval |

Observe 的目标不是监控炫技。

它是让系统可以被接管。

## 四者如何配合

一个客服 AI 项目里：

- RAG 负责找到正确政策和历史案例。
- Agent 负责生成回复草稿或创建工单。
- Eval 负责判断回答是否合格。
- Observe 负责记录线上表现和失败样本。

四者合起来，才像一个生产系统。

如果只有 RAG，没有 Eval，团队只能说“看起来答得不错”。

如果只有 Agent，没有 Observe，系统出了问题很难定位。

如果只有 Observe，没有反馈闭环，线上错误只是被看见，并没有变好。

## 实战拆解：退款咨询助手需要哪四类工具

假设我们做一个退款咨询助手。

用户问：“我的订单显示退款中，钱什么时候到账？”

RAG 要能找到退款政策、渠道规则和订单状态解释。

Agent 要能读取订单状态，必要时生成工单草稿，但不能直接承诺退款。

Eval 要检查：

- 是否引用正确政策。
- 是否解释订单状态。
- 是否避免过度承诺。
- 高金额退款是否转人工。

Observe 要记录：

- 用户问题。
- 检索到的资料。
- 模型输出。
- 客服是否采纳。
- 是否发生人工修改。

这样，这个助手才不是一个“会回答”的工具，而是一套能被评测、被观察、被接管的系统。

## 最小能力表

| 项目阶段 | 必备能力 |
| --- | --- |
| Demo | RAG 或 Agent 原型，少量人工评测 |
| 试点 | 样本库、回放、工具权限、trace |
| 生产 | SLO、告警、成本监控、回滚和接管 |

FDE 选工具时，不要把这四类能力互相替代。

会搭 RAG 不等于有 Eval，会做 Agent 不等于有 Observe。
