# RAG、Agent、Eval、Observe 分别需要什么工具

FDE 做企业 AI 项目，常常会同时听到四个词：RAG、Agent、Eval、Observe。

这四件事经常被混在一起，但它们解决的问题完全不同。RAG 解决知识和数据如何进入模型，Agent 解决模型如何调用工具执行任务，Eval 解决质量如何判断，Observe 解决系统运行后如何被看见。

从定义上看，这四类能力构成企业 AI 生产化的基本控制面。少了任何一类，项目都容易停在 Demo。

> **一句可以带走的判断：RAG 让 AI 有知识，Agent 让 AI 有动作，Eval 让 AI 有标准，Observe 让 AI 有责任。**

## RAG 需要什么工具

RAG 工具要解决知识处理问题。

| 能力 | 说明 |
| --- | --- |
| 文档解析 | 处理 PDF、Word、网页、表格 |
| 切分和清洗 | 让知识块可检索 |
| 向量库 | 存储和召回知识 |
| Rerank | 提高检索相关性 |
| 引用溯源 | 让答案有证据 |

FDE 做 RAG 时，最怕只追求“能回答”，而忽略知识来源、权限和更新机制。

## Agent 需要什么工具

Agent 工具要解决行动问题。

| 能力 | 说明 |
| --- | --- |
| 工具注册 | 定义 Agent 可调用能力 |
| 权限分级 | 控制只读、建议、写入 |
| 状态管理 | 管理计划、执行、观察、重试 |
| 审批节点 | 高风险动作人工确认 |
| 执行 trace | 回放每一步动作 |

Agent 的工具层越强，越要小心权限边界。

## Eval 需要什么工具

Eval 工具要解决质量问题。

| 能力 | 说明 |
| --- | --- |
| 样本管理 | 正例、反例、边界样本 |
| 自动评测 | 格式、引用、准确性、拒答 |
| 人工标注 | 专家判断和业务验收 |
| 回放测试 | 变更后复查旧样本 |
| 失败分析 | 聚类和根因标注 |

没有 Eval，AI 项目只能靠感觉迭代。

## Observe 需要什么工具

Observe 工具要解决运行问题。

| 能力 | 说明 |
| --- | --- |
| 日志 | 记录事件 |
| 指标 | 看成功率、延迟、成本 |
| Trace | 看请求链路 |
| 告警 | 异常时通知 Owner |
| 反馈 | 收集用户修改和失败样本 |

Observe 的目标不是监控炫技，而是让系统可以被接管。

## 四者如何配合

一个客服 AI 项目里：

- RAG 负责找到正确政策和历史案例。
- Agent 负责生成回复草稿或创建工单。
- Eval 负责判断回答是否合格。
- Observe 负责记录线上表现和失败样本。

四者合起来，才像一个生产系统。

## 最小能力表

| 项目阶段 | 必备能力 |
| --- | --- |
| Demo | RAG 或 Agent 原型，少量人工评测 |
| 试点 | 样本库、回放、工具权限、trace |
| 生产 | SLO、告警、成本监控、回滚和接管 |

FDE 选工具时，不要把这四类能力互相替代。会搭 RAG 不等于有 Eval，会做 Agent 不等于有 Observe。
