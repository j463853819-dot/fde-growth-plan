# 03-CDEF 方法论

CDEF 是这个知识库的核心方法论资产，用来解释 FDE 如何从混沌现场推进到可交付系统。

它不是一套抽象流程图，而是一条项目推进路径：先读懂现场，再设计切片，然后工程验证，最后把反馈沉淀为产品和组织能力。

## 四阶段

| 阶段 | 核心问题 | 主要产物 |
| --- | --- | --- |
| Context | 现场到底发生了什么 | 事实约束表、角色地图、问题模型 |
| Design | 哪个切片最值得验证 | 需求切片画布、方案草图、门禁标准 |
| Engineer | 如何从 Demo 走到可运行系统 | 原型、评测、ADR、生产准入证据 |
| Feedback | 如何证明有效并反哺产品 | 指标复盘、客户接管、产品反哺清单 |

## 教材化拆解

CDEF 可以进一步拆成四个可训练模块。每个模块都不是一句口号，而是一组现场方法、交付物和常见陷阱。

### 03-现场勘探（Context）

Context 的重点不是“调研客户需求”，而是把现场还原成可验证的问题结构。

- 三层访谈法：决策者、业务骨干、技术接口人分别访谈，避免只听一个视角。
- 需求挖掘三层法：从表面诉求进入业务瓶颈，再追到根本问题。
- 问题定义文档（PDD）：把事实、影响、约束、假设和待验证问题写清楚。
- 常见陷阱：过早做方案、被客户带偏、信息收集过度。

### 04-方案设计（Design）

Design 的重点不是画一个完整大系统，而是在不完全信息下选出最值得验证的路径。

- 技术决策框架：可行性、成本、时间、可维护性四维评估。
- 架构取舍：用 ADR 记录为什么选这个方案、放弃哪些方案。
- 不完全信息下的设计策略：先切小闭环，再把风险暴露到试点里。
- 设计交付物：方案文档、成功指标、风险清单。

### 05-工程交付（Engineer）

Engineer 的重点不是把 Demo 补完，而是把系统推进到真实责任边界里。

- Bootcamp 5 天极限工作法：用短周期完成现场对齐、原型、评测和试点准备。
- 原型到试点到生产：三阶段门禁，逐步放开数据、用户、权限和自动化范围。
- 灰度发布：Canary、EA、Broad、Full，控制风险扩散。
- 5 分钟回滚机制：上线前必须确认能快速降级、撤回或人工接管。

### 06-持续反馈（Feedback）

Feedback 的重点不是收集满意度，而是证明价值、完成接管，并把现场学习沉淀出来。

- 价值验证：业务指标、用户采纳、系统稳定性三条线一起看。
- 交接标准：客户能独立运行、解释、回滚和继续迭代。
- 反馈驱动迭代：FDE 最反直觉的一点是，干得越好，越会离开。
- 产品反哺：把现场洞察变成平台能力、模板、组件或方法论。
