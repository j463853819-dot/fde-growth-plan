# Engineer 工程：从 Demo 到可运行系统

Engineer 阶段是 FDE 最容易被误解的一段。

很多人以为它只是“把 Demo 做完整”。但在 CDEF 里，Engineer 的真正任务是把一个被验证过的价值切片，推进成可以试点、可以上线、可以被接管的系统能力。

从定义上看，Engineer 是 CDEF 的第三阶段，负责原型实现、系统集成、评测回放、权限控制、可观测性、生产门禁和交付证据。它不是单纯编码阶段，而是从可能性到可靠性的工程转化。

> **一句可以带走的判断：Engineer 阶段不是把功能补完，而是把系统带进真实责任。**

## Demo 要保留假设意识

Demo 阶段可以简化，但不能假装没有简化。

FDE 在 Engineer 阶段要记录：

- 哪些数据是样例数据？
- 哪些权限是临时权限？
- 哪些异常路径没有覆盖？
- 哪些操作还没有审计？
- 哪些指标还没有稳定观测？

这些记录会进入交付证据包，避免 Demo 成功之后产生错觉。

## 从 Demo 到试点

试点不是扩大演示，而是让真实用户进入有限真实场景。

| Demo 阶段 | 试点阶段 |
| --- | --- |
| 样例用户 | 真实用户 |
| 样例数据 | 授权数据 |
| 演示路径 | 真实流程 |
| 人工解释异常 | 记录并处理异常 |
| 看反馈 | 看采用和指标变化 |

试点的价值，是让系统暴露真实问题。一个没有暴露问题的试点，反而值得警惕。

## 工程化要补哪些能力

Engineer 阶段至少要补齐六件事：

| 能力 | 说明 |
| --- | --- |
| 数据链路 | 数据来源、更新、质量和权限过滤 |
| 权限控制 | 身份、角色、工具调用和审计 |
| 评测回放 | 样本集、失败样本、回归测试 |
| 可观测性 | 日志、指标、trace、成本和延迟 |
| 失败处理 | 降级、回滚、人工接管 |
| 交付证据 | ADR、Owner、门禁、运行手册 |

这些不是大公司才需要的复杂流程，而是系统进入生产的基本安全带。

## 一个 Agent 项目的工程路径

假设 Design 阶段切出一个“自动创建工单 Agent”。

Engineer 阶段可以这样推进：

| 阶段 | 工程动作 |
| --- | --- |
| 原型 | 用历史对话生成工单草稿 |
| 试点 | 只允许人工确认后创建工单 |
| 评测 | 建立分类准确率、重复工单率、人工修改率 |
| 权限 | Agent 只读对话和客户资料，不自动关闭工单 |
| 观测 | 记录每次工具调用和失败原因 |
| 生产 | 开放低风险类别自动创建，高风险转人工 |

这里的关键不是“Agent 能不能创建工单”，而是“它在什么边界下被允许创建工单”。

## Engineer 阶段的退出标准

Engineer 结束时，不能只交代码。

至少要交：

- 可运行系统或试点版本。
- 评测集和回放结果。
- 架构决策记录。
- 权限和工具调用清单。
- 监控指标和告警规则。
- 风险、回滚和人工接管方案。
- 客户接管前的开放问题。

Engineer 阶段的成熟标志，是系统不再只依赖 FDE 个人理解，而开始拥有可复查、可运行、可交接的证据。
