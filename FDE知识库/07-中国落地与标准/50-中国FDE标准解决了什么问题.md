# 中国 FDE 标准解决了什么问题

一家 AI 公司最开始做 FDE，往往靠几个特别强的人。

他们能见客户、懂业务、写 Demo、接系统、处理上线问题。客户喜欢他们，销售依赖他们，老板也觉得这就是 FDE 的价值。

但项目一多，问题就出来了。新人不知道访谈该问什么，Demo 做完不知道怎么判断是否进入试点，上线前没有统一门禁，客户接管靠口头交接，项目复盘也只停在会议纪要里。

这时团队才会发现：FDE 如果只靠个人能力，很难规模化。

> **一句可以带走的判断：FDE 标准的价值，不是把人框死，而是把个人经验变成组织可以复制的能力。**

## 理论框架

中国 FDE 标准，是一套围绕岗位能力、项目流程、交付证据、生产门禁和客户接管的规范体系。

它解决的不是“给岗位取名”，而是让 FDE 工作可识别、可训练、可交付、可复查。

| 问题 | 标准化作用 |
| --- | --- |
| 岗位边界不清 | 明确 FDE 和售前、交付、咨询的区别 |
| 项目过程不可复查 | 固定 CDEF、门禁和证据包 |
| 质量依赖个人 | 建立能力模型和模板 |
| 客户接管困难 | 标准化运行手册和接管清单 |
| 产品反哺缺失 | 要求复盘和可复用资产沉淀 |

标准不是把所有项目做成一样，而是让每个项目至少留下同样可复查的骨架。

## 核心方法

一个最小 FDE 标准包，可以包含五层。

| 标准项 | 内容 |
| --- | --- |
| 岗位能力标准 | 现场发现、工程实现、AI 生产化、客户接管 |
| 项目流程标准 | Context、Design、Engineer、Feedback |
| 交付证据标准 | 事实表、ADR、评测、SLO、接管清单 |
| 生产门禁标准 | 原型、试点、生产、接管 |
| 复盘标准 | 业务结果、失败样本、产品反哺 |

好的标准应该管住关键风险，而不是限制现场判断。

它要明确哪些材料必须有、哪些门禁必须过、哪些风险必须记录、哪些 Owner 必须明确、哪些经验必须沉淀。具体行业、系统和场景，仍然需要 FDE 灵活判断。

## 实战拆解：标准如何防止 FDE 变成外包

一个客户上线客服 AI 后，又提出一堆“顺便”的需求：顺便做个报表，顺便接一个知识库，顺便改一下运营后台，顺便帮他们整理失败样本。

如果没有标准，FDE 团队很容易为了客户满意全部接住。短期客户开心，长期团队会被拖成定制交付。

有标准后，团队会先问：

- 这个需求属于当前价值切片吗？
- 是否影响上线门禁？
- 是否有业务 Owner？
- 是否有复用价值？
- 是否应该进入下一轮迭代，而不是当前交付范围？

标准不是为了拒绝客户。

它是为了让需求进入正确的位置：当前价值闭环必须做，可复用能力进入产品路线，单点定制单独报价，低价值需求延后或拒绝。

## 最后判断

中国市场客户多、项目杂、预算敏感。如果每个项目都靠高级 FDE 深度定制，成本很难成立。

标准化不是 FDE 的束缚，而是 FDE 从个人英雄变成组织能力的桥。它让现场判断可以被训练，让交付质量可以被复查，让项目经验可以被复用。
