# 国内 FDE 岗位和海外有什么不同

国内很多岗位开始叫 FDE，但实际工作内容差异很大。

有的更像售前解决方案，有的更像交付工程师，有的更像 AI 应用顾问，有的真的在做现场工程。名字一样，不代表岗位一样。

从定义上看，海外 FDE 更强调工程能力前移、客户现场验证和产品反哺；国内 FDE 往往叠加了售前、交付、私有化部署、客户培训、项目管理和定制开发等职责。

> **一句可以带走的判断：国内 FDE 最大的风险，是名字变高级了，工作却仍然停在低毛利交付。**

## 岗位差异

| 维度 | 海外典型 FDE | 国内常见 FDE |
| --- | --- | --- |
| 商业基础 | 高客单价、重结果 | 项目制、预算敏感 |
| 工作边界 | 现场工程 + 产品反哺 | 售前、交付、定制混合 |
| 技术重点 | 平台能力、数据建模、生产系统 | 私有化、集成、AI 应用搭建 |
| 组织地位 | 靠近核心产品和战略客户 | 容易被放在交付或解决方案团队 |
| 成功标准 | 业务结果和可复用产品能力 | 项目验收和客户满意 |

国内 FDE 更容易被拉进“什么都做”的状态。

## 国内 FDE 更需要边界感

国内客户常常希望一个团队同时解决：

- 售前方案。
- 原型演示。
- 私有化部署。
- 数据接入。
- 定制开发。
- 培训运维。
- 后续修改。

如果没有边界，FDE 会很快变成高级外包。

## 国内 FDE 的机会

国内市场也有优势：

- 行业场景足够丰富。
- 传统行业 AI 改造需求真实。
- 工程人才供给强。
- AI 工具链迭代快。
- 客户愿意试点，但需要更强价值证明。

机会在于用标准化方法把项目制经验沉淀下来。

## 岗位判断表

| 问题 | 更像 FDE 吗 |
| --- | --- |
| 是否重新定义现场问题 | 是 |
| 是否动手构建和验证系统 | 是 |
| 是否参与生产化和接管 | 是 |
| 是否把经验反哺产品 | 是 |
| 是否只是做演示和验收 | 更像售前/交付 |

国内 FDE 要成立，必须从岗位名回到工作对象：真实现场、工程验证、生产责任和产品反哺。
