# 07-中国落地与标准

同样叫 FDE，在中国现场经常会长成另一种样子。

海外语境里，FDE 更容易被理解成“工程师前移到客户现场”，用工程能力解决真实业务问题，并把经验反哺产品。但在中国，客户常常还会额外提出私有化部署、等保审计、信创适配、本地数据闭环、项目验收材料、现场培训和售后响应。

这意味着，中国 FDE 不能只是照搬一个岗位名。

它必须同时处理四件事：真实现场、AI 工程、合规交付和标准化复制。少一个，项目都容易滑向售前、外包、定制开发或一次性项目制。

> **一句可以带走的判断：中国 FDE 的机会不在照搬海外岗位名，而在把现场工程、AI 生产化、合规交付和行业 Know-how 组织成可复制能力。**

## 本章解决什么问题

这一章关注 FDE 在中国市场为什么会变形，以及这种变形里哪些是噪音，哪些是真正的机会。

| 问题 | 本章回答 |
| --- | --- |
| 为什么不能直接照搬海外 FDE | 中国客户的采购、合规、私有化和交付传统不同 |
| 国内 FDE 岗位为什么容易混杂 | 售前、交付、咨询、实施、研发常被压到一个角色里 |
| 标准化为什么重要 | 没有标准，FDE 很容易变成个人英雄或高级外包 |
| 合规和私有化如何影响项目 | 它们不是部署细节，而是方案设计输入 |
| 中国有哪些玩家会进入 FDE 位置 | 大模型、云厂商、ISV、集成商、咨询、传统软件和内部团队 |

## 本章的核心判断

中国 FDE 的难点，不只是“客户需求复杂”。真正的难点是：客户现场往往同时有业务问题、系统遗留、采购边界、合规约束、私有化环境和项目制交付习惯。

所以，中国 FDE 更像一个复合能力：

| 能力 | 说明 |
| --- | --- |
| 现场问题定义 | 能从客户模糊需求里拆出真实流程瓶颈 |
| AI 工程交付 | 能把模型、RAG、Agent、评测、观测放进系统 |
| 合规生产化 | 能处理数据不出域、审计、权限、私有化和信创适配 |
| 标准化复制 | 能把项目经验沉淀成模板、组件、方法和产品能力 |

如果只会现场沟通，会变成咨询；只会写代码，会变成实施；只会做客户定制，会变成外包；只有把这四件事连起来，FDE 才能在中国市场成立。
