# 标准化交付和岗位职能的差异

很多公司谈 FDE，容易先谈岗位：招什么人、叫什么 title、放在哪个部门。

但在中国市场，更应该先谈标准化交付。因为如果交付方法不标准，岗位再高级，也会被项目现场拖成救火队。

从定义上看，岗位职能回答“这个人做什么”，标准化交付回答“这类项目怎么被稳定完成”。FDE 要成立，不能只靠岗位描述，还要靠流程、模板、门禁、证据和接管机制。

> **一句可以带走的判断：FDE 的组织化，不是多招几个厉害的人，而是让厉害的人做出的判断可以被复用。**

## 岗位职能的局限

岗位 JD 常常写：

- 懂业务。
- 懂技术。
- 能沟通。
- 能驻场。
- 能做 AI 交付。

这些都对，但不够。因为它没有回答项目如何从模糊需求走到生产系统。

## 标准化交付要补什么

| 标准 | 解决什么 |
| --- | --- |
| CDEF 流程 | 项目如何推进 |
| 事实约束表 | 现场如何被记录 |
| 需求切片画布 | 需求如何被验证 |
| ADR | 决策如何被复查 |
| 生产门禁 | 上线如何被判断 |
| 接管清单 | 客户如何持续运行 |

标准化交付不是替代 FDE，而是放大 FDE。

## 岗位和流程的关系

| 只看岗位 | 加上交付标准 |
| --- | --- |
| 依赖个人经验 | 经验可训练 |
| 项目质量不稳定 | 质量可复查 |
| 做完就散 | 经验可沉淀 |
| 客户持续依赖个人 | 客户能接管 |

## 中国市场为什么更需要标准化

中国市场客户多、项目杂、预算敏感。如果每个项目都靠高级 FDE 深度定制，成本很难成立。

标准化能帮助团队：

- 降低新人培养成本。
- 缩短项目启动时间。
- 减少交付风险。
- 提升客户信任。
- 把项目经验产品化。

## 最后的判断

FDE 的未来，不是岗位名越来越多，而是方法越来越可复制。

当一个团队能稳定把现场问题变成生产系统，并让客户接管，这才说明它真的拥有 FDE 能力。
