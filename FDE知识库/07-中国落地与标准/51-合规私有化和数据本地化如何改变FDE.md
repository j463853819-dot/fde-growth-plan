# 合规、私有化和数据本地化如何改变 FDE

在中国做 FDE，绕不开合规、私有化和数据本地化。

这不是项目后期的部署细节，而是从一开始就会改变问题定义、方案设计、工具选型、交付成本和客户接管方式。

从定义上看，合规、私有化和数据本地化，是对 AI/FDE 项目中数据流动、模型部署、系统集成、审计留痕和运行责任的约束集合。它们决定了技术能力能以什么方式进入组织。

> **一句可以带走的判断：在中国，FDE 不懂合规和私有化，就很难真正进入生产。**

## 它们改变什么

| 约束 | 改变 |
| --- | --- |
| 数据不出域 | 影响模型调用、RAG 架构和部署方式 |
| 私有化部署 | 增加环境适配、运维和升级成本 |
| 信创要求 | 影响数据库、中间件、操作系统和工具链 |
| 等保审计 | 要求日志、权限、访问控制和安全测评 |
| 行业监管 | 限制自动决策和数据使用范围 |

这些约束越晚发现，返工越大。

## 对 FDE 工作方式的影响

FDE 需要在 Context 阶段就问：

- 数据能不能出域？
- 是否允许调用外部模型？
- 客户是否要求私有化？
- 现有环境是否信创？
- 谁有权审批数据访问？
- 日志和审计保存多久？

这些问题不是安全团队的后置检查，而是方案设计的输入。

## 一个例子

客户想做合同审查 AI。

如果数据可以使用云端模型，Demo 很快；但如果合同数据不能出域，就要考虑：

- 私有模型或本地推理。
- 本地向量库。
- 权限分级。
- 审计日志。
- 评测集脱敏。
- 客户环境部署和升级。

这会直接改变交付周期和成本。

## 合规不是负担，也可能是壁垒

如果团队能把合规做成标准能力，就会形成壁垒。

比如：

- 标准数据分级清单。
- 私有化部署模板。
- 权限和审计组件。
- 等保材料模板。
- 敏感信息过滤和脱敏流程。

这些能力一旦沉淀，就能让 FDE 在高约束行业更快落地。
