# FDE 为什么容易变成外包

FDE 和外包之间只有一线之隔。

FDE 进入客户现场，理解客户需求，动手解决问题。如果没有边界、没有产品反哺、没有退出机制，它很容易变成“客户说什么就做什么”的高级外包。

> **一句可以带走的判断：FDE 不是不能做定制，而是不能让定制吞掉判断、复用和接管。**

## 变成外包的信号

| 信号 | 问题 |
| --- | --- |
| 客户说什么都做 | 没有问题重定义 |
| 每个项目从零开始 | 没有复用资产 |
| 做完功能就走 | 没有生产接管 |
| FDE 长期代运维 | 客户没有能力接住 |
| 没有产品反哺 | 现场经验沉淀不了 |
| 按人天定价 | 价值被压成劳动力 |

## FDE 和外包的关键差异

| 维度 | 外包 | FDE |
| --- | --- | --- |
| 起点 | 客户需求 | 现场真实问题 |
| 目标 | 完成范围 | 产生业务结果 |
| 方法 | 按单执行 | 验证、生产、反哺 |
| 交付物 | 功能和代码 | 可运行能力和证据 |
| 结束条件 | 验收 | 接管和复用 |

## 如何避免

- 每个需求都先做问题重定义。
- 每个项目都要有需求切片。
- 每个关键取舍都写 ADR。
- 每个上线都要有接管清单。
- 每个项目结束都要产品反哺。
- 明确哪些需求不做。

## 最后的判断

FDE 可以深入现场，但不能被现场吞没。

真正的 FDE 要能从客户现场走出来，把一次复杂项目变成下一次更快、更稳、更可复用的能力。
