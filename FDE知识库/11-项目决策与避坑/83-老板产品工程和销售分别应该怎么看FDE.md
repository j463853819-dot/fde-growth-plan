# 老板、产品、工程和销售分别应该怎么看 FDE

FDE 在组织里容易被误解，因为不同角色看到的是不同东西。

老板看战略和收入，产品看路线图，工程看系统边界，销售看客户推进。FDE 如果不能让这些角色形成共同语言，就会被拉扯成救火队。

> **一句可以带走的判断：FDE 是组织协作位置，不是某个部门的万能补丁。**

## 老板怎么看

老板要问：

- FDE 是否能提升大客户成功率？
- 是否能把 AI 从试点推进到收入？
- 是否能沉淀行业能力？
- 是否会变成高成本外包？

老板不该只看项目数量，而要看复用率、续费率和产品反哺。

## 产品怎么看

产品要问：

- 现场需求里哪些是共性？
- 哪些应该进入产品路线？
- 哪些只是配置或项目定制？
- FDE 是否带回了失败样本和真实用法？

产品不能把 FDE 当成需求收集员。FDE 带回来的不是“客户想要什么”，而是“现场真实流程如何工作”。

## 工程怎么看

工程要问：

- FDE 做的东西是否符合系统边界？
- 哪些原型能进入生产？
- 哪些临时方案必须重构？
- 权限、评测、SLO 和回滚是否清楚？

工程不能只抱怨 FDE 做得粗，也不能让所有现场问题都绕过平台。

## 销售怎么看

销售要问：

- FDE 是否帮助客户看见真实价值？
- Demo 是否能推进采购决策？
- 试点结果是否能支撑合同？
- 哪些承诺不能随便说？

销售不能把 FDE 当成免费售前，也不能把所有客户想法都包装成可交付承诺。

## 共同语言

| 角色 | 应共同关注 |
| --- | --- |
| 老板 | 收入、复用、战略客户 |
| 产品 | 共性需求、路线图、模板 |
| 工程 | 生产边界、质量、平台能力 |
| 销售 | 价值证明、采购推进、风险承诺 |
| FDE | 现场事实、工程验证、业务结果 |

FDE 要站在这些角色之间，但不能替代任何一个角色。
