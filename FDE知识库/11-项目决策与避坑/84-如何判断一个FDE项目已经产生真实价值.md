# 如何判断一个 FDE 项目已经产生真实价值

FDE 项目不能只用“上线了”“客户满意”“Demo 很好”来判断价值。

真实价值必须体现在工作流、业务指标、用户采用、系统接管和产品反哺上。否则项目可能只是完成了一次交付，没有改变组织能力。

> **一句可以带走的判断：FDE 的真实价值，不是系统存在，而是工作方式发生了可衡量变化。**

## 五类价值信号

| 信号 | 说明 |
| --- | --- |
| 流程变化 | 用户真的改变了工作动作 |
| 指标变化 | 时间、成本、质量、风险或收入改善 |
| 用户采用 | 真实用户持续使用，而不是只试一次 |
| 客户接管 | 客户能运行、复查、回滚和继续演进 |
| 产品反哺 | 项目经验变成模板、组件或产品能力 |

## 不能算真实价值的信号

| 信号 | 为什么不够 |
| --- | --- |
| Demo 很炫 | 只证明可能性 |
| 客户说不错 | 可能只是礼貌反馈 |
| 功能上线 | 不代表被使用 |
| 模型效果好 | 不代表进入工作流 |
| 项目验收 | 不代表持续产生结果 |

## 价值证明表

| 维度 | 证据 |
| --- | --- |
| 效率 | 平均处理时长下降 |
| 质量 | 错误率、返工率下降 |
| 风险 | 高风险场景转人工率提升 |
| 采用 | 周活用户、采纳率、修改率 |
| 接管 | 客户完成演练和运行手册 |
| 复用 | 形成模板、组件或产品需求 |

## 一个例子

客服 AI 助手上线后，如果只是“能回答问题”，价值还不够。

更有说服力的证据是：

- 退款咨询平均响应时间下降 35%。
- 客服建议采纳率 68%。
- 高金额退款 100% 转人工。
- 每周失败样本进入评测集。
- 客服主管能维护知识库和查看告警。
- 同一套模板复制到物流咨询场景。

这才说明项目产生了真实价值。

## 最后的判断

FDE 项目的终点不是交付完成，而是价值被证明、责任被接住、经验被复用。

如果这三件事没有发生，项目再热闹，也只是一次不错的演示。
