# 第一个 FDE 项目应该选什么场景

第一个 FDE 项目不要选最宏大的场景。

很多团队一开始就想做企业级 AI 中台、全流程 Agent、管理驾驶舱或智能运营大脑。愿景很大，但失败概率也高。第一个项目更应该选小而真实、可验证、可接管的场景。

> **一句可以带走的判断：第一个 FDE 项目，不要证明你能做多大，要证明你能把一个真实闭环做成。**

## 好场景的标准

| 标准 | 说明 |
| --- | --- |
| 高频 | 不是偶发问题 |
| 痛感明确 | 用户真的受影响 |
| 输入可得 | 数据或文档能拿到 |
| 风险可控 | 出错能人工兜底 |
| 指标清楚 | 能衡量改善 |
| 接管简单 | 客户能理解和维护 |

## 适合作为第一个项目的场景

| 场景 | 为什么适合 |
| --- | --- |
| 客服建议回复 | 高频、指标清楚、可人工确认 |
| 销售线索摘要 | 输入明确、价值容易感知 |
| 会议纪要到行动项 | 风险低、反馈快 |
| 知识库问答加引用 | 容易验证检索质量 |
| 工单分类和分流 | 结果可衡量 |
| 日报异常解释 | 有业务价值，但要控制范围 |

## 不建议作为第一个项目

| 场景 | 风险 |
| --- | --- |
| 全自动审批 | 责任太重 |
| 企业级 AI 中台 | 范围太大 |
| 全流程无人 Agent | 权限和回滚复杂 |
| 高风险医疗/金融决策 | 评测和合规门槛高 |
| 多部门综合驾驶舱 | 指标口径容易失控 |

## 选择公式

第一个项目最好满足：

```text
高频 + 可控风险 + 明确指标 + 可人工确认 + 可扩展
```

做成第一个小闭环，比讲清一个宏大蓝图更有价值。
