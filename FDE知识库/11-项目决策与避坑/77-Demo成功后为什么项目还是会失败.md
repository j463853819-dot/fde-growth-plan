# Demo 成功后为什么项目还是会失败

很多 AI/FDE 项目不是死在 Demo 前，而是死在 Demo 后。

Demo 成功会制造一种乐观错觉：既然已经能跑，那项目应该快上线了。现实往往相反。Demo 之后，数据、权限、流程、评测、成本、责任和接管问题才真正出现。

> **一句可以带走的判断：Demo 成功只证明方向可能对，不证明组织已经准备好接住它。**

## 常见失败原因

| 原因 | 表现 |
| --- | --- |
| 数据不可持续 | Demo 用样例数据，生产数据接不上 |
| 权限没设计 | 真实用户看不到该看的，或看到不该看的 |
| 没有评测标准 | 大家觉得不错，但不知道能不能上线 |
| 不进入工作流 | 用户还要多开一个工具 |
| 没有 Owner | 出问题后没人负责 |
| 客户无法接管 | 系统只能靠 FDE 团队维护 |
| ROI 不清楚 | 客户看完热闹，但不愿继续付费 |

## Demo 后要立刻做什么

Demo 成功后，不要急着扩功能。

先补四件事：

1. 写清楚 Demo 验证了什么。
2. 写清楚 Demo 绕过了什么。
3. 定义试点范围和成功指标。
4. 列出进入生产前必须补的证据。

## 三个关键问题

- 用户是否愿意在真实流程里使用？
- 系统输出是否能被评测和追责？
- 客户组织是否有人愿意接管？

如果这三个问题没有答案，Demo 越成功，后面的失望越大。

## 正确心态

Demo 不是项目完成的信号，而是项目进入下一阶段的证据。

FDE 要做的，不是让客户鼓掌，而是让客户和团队一起看清：哪些假设成立了，哪些风险还没解决，下一步该试点、缩小还是停止。
