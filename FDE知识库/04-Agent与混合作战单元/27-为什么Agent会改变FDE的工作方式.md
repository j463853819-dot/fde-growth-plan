# 为什么 Agent 会改变 FDE 的工作方式

Agent 改变 FDE，不是因为它能聊天，而是因为它开始能执行。

过去 AI 更像一个能力增强工具：帮你写文案、总结资料、生成代码片段。Agent 不一样，它可以理解目标、拆分任务、调用工具、读取系统、写入结果，甚至参与一段业务流程。

从定义上看，Agent 是一种能在给定目标和权限范围内，通过模型推理、工具调用和状态管理完成任务的 AI 系统。它不只是输出文本，而是能够参与行动链条。

> **一句可以带走的判断：Agent 让 FDE 从“自己动手解决问题”，转向“设计一组人机协同的解决问题系统”。**

## 传统 FDE 的瓶颈

传统 FDE 很强，但也有瓶颈。

| 瓶颈 | 表现 |
| --- | --- |
| 信息处理量有限 | 现场文档、日志、访谈和工单太多 |
| 原型速度受限 | 需求变化快，代码和集成跟不上 |
| 重复任务多 | 数据清洗、测试、文档、复盘反复出现 |
| 运维压力大 | 上线后还要盯指标、失败样本和客户反馈 |

Agent 不能替代 FDE 的判断，但可以放大 FDE 的处理能力。

## Agent 能接管哪些环节

在 FDE 项目里，Agent 适合接管可定义、可验证、可回放的任务。

| 环节 | Agent 可以做什么 | 人必须负责什么 |
| --- | --- | --- |
| Context | 整理访谈纪要、抽取流程和角色 | 判断真实问题和政治边界 |
| Design | 生成方案草图、列出风险清单 | 选择价值切片和取舍 |
| Engineer | 辅助开发、测试、生成文档 | 设计架构和生产边界 |
| Feedback | 汇总失败样本、生成复盘草稿 | 判断产品化方向 |

Agent 越靠近执行动作，人类越要设计边界。

## FDE 的工作重心如何变化

Agent 时代，FDE 的重心会从“单点手艺”转向“系统指挥”。

过去，优秀 FDE 靠自己能写、能查、能沟通、能救火。未来，优秀 FDE 还要能设计 Agent 的任务、权限、评测和接管机制。

这意味着 FDE 要多三种能力：

- 任务编排能力：知道哪些工作适合交给 Agent。
- 控制面设计能力：知道 Agent 可以看什么、做什么、什么时候停。
- 质量运营能力：知道如何通过评测、trace 和反馈持续改进 Agent。

## 风险也被放大

Agent 放大效率，也放大风险。

一个人做错事，错误路径通常可追溯；一个 Agent 如果权限设计不好，可能在短时间内重复错误、扩大影响、制造难以定位的链路问题。

所以 Agent 改变 FDE 的同时，也要求 FDE 更重视：

- 工具权限分级。
- 状态机。
- 执行 trace。
- 成本限流。
- 人工确认点。
- 回滚和降级。

Agent 时代不是更轻松的时代，而是更需要工程纪律的时代。
