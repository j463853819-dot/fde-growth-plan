# ROI 与价值证明卡模板

ROI 与价值证明卡用于把 FDE 项目的业务价值说清楚。

它解决的问题是：项目不是“感觉有用”，而是到底改善了哪个指标，成本是多少，是否值得继续投。

> **价值证明卡不是复盘装饰，而是续费、扩场景和停止投入的决策依据。**

## 一句话定义

ROI 与价值证明卡是一张把业务场景、基线指标、改善目标、实际结果、总拥有成本、收益归因和下一步决策放在一起的价值判断表。

## 价值证明卡

| 字段 | 内容 |
| --- | --- |
| 项目名称 |  |
| 业务场景 |  |
| 目标角色 |  |
| 原始问题 |  |
| 基线指标 | 当前时间、成本、质量、风险或收入 |
| 改善目标 | 希望改善多少 |
| 实际结果 | 试点或生产后的指标 |
| 总拥有成本 | 人力、平台、模型、集成、运维 |
| 直接收益 | 节省工时、降低成本、提升收入 |
| 间接收益 | 风险减少、体验提升、知识沉淀 |
| 归因说明 | 哪些收益能归因于本项目 |
| 结论 | 继续、扩大、调整或停止 |

## ROI 简化计算

```text
ROI =（效率收益 + 收入提升 + 风险减少收益 - 总拥有成本）/ 总拥有成本
```

## 使用提醒

ROI 不应该上线后才算。

FDE 在选择场景时就要问：这个项目未来如何证明价值？如果基线不可测、收益不可归因、客户不愿提供数据，那就不要轻易承诺按效果付费。

## 价值归因说明怎么写

ROI 最难的不是公式，而是归因。FDE 要避免把所有业务改善都算到 AI 项目头上。

| 问题 | 写法 |
| --- | --- |
| 哪些改善来自本项目 | 说明 AI 改变了哪个流程动作 |
| 哪些改善来自其他因素 | 排除促销、组织调整、季节波动等影响 |
| 数据来自哪里 | 标明系统报表、抽样复核或人工统计 |
| 结果是否可持续 | 看是否连续多周稳定，而不是单周峰值 |

## 价值证明示例

| 字段 | 内容 |
| --- | --- |
| 项目名称 | 客服退款咨询 AI 建议回复 |
| 业务场景 | 客服处理退款政策和退款进度咨询 |
| 基线指标 | 平均响应 8.6 分钟，人工查政策平均 3 次切换 |
| 改善目标 | 平均响应下降 30%，建议采纳率超过 60% |
| 实际结果 | 试点 4 周后平均响应 5.1 分钟，采纳率 67% |
| 总拥有成本 | FDE、平台、模型、集成和运营维护成本 |
| 直接收益 | 节省客服处理时间 |
| 间接收益 | 政策口径更一致，投诉风险下降 |
| 归因说明 | 只统计退款咨询场景，排除活动高峰周 |
| 结论 | 扩大到物流咨询，但不进入全自动退款 |

## 常见错误

- 没有基线，后面只能讲感觉。
- 只算模型调用成本，不算维护和运营成本。
- 只算效率收益，不算质量和风险。
- 把短期试点结果直接外推全年。
- 没有写“继续、扩大、调整或停止”的结论。

## 完成标准

价值证明卡完成后，团队至少要能回答：

1. 原来是什么样。
2. 项目改善了什么。
3. 改善是否可归因。
4. 总成本是多少。
5. 下一步是继续、扩大、调整还是停止。

## 可以带走的判断

ROI 不是为了证明项目一定成功，而是为了让团队更早知道这个场景还值不值得继续投入。
