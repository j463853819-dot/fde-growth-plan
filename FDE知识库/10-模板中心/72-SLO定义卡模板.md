# SLO 定义卡模板

SLO 定义卡用于把业务承诺转成可观测指标。

它解决的问题是：系统上线后，客户怎么知道它是不是健康，出了问题谁响应，什么时候需要降级或回滚。

> **SLO 不是运维指标，而是业务承诺的可观测版本。**

## 一句话定义

SLO 定义卡是一张把系统或 AI 场景的业务承诺、SLI 指标、目标阈值、告警条件、Owner、降级和回滚方式写清楚的运行卡。

## 模板

| 字段 | 内容 |
| --- | --- |
| 系统/场景名称 |  |
| 业务承诺 | 这个系统对业务承诺什么结果 |
| 用户范围 | 谁使用，什么时候使用 |
| SLI 指标 | 用什么指标观测 |
| SLO 目标 | 目标阈值 |
| 观察窗口 | 按小时、天、周还是月 |
| 告警条件 | 低于什么标准触发告警 |
| 告警等级 | P0/P1/P2/P3 |
| Owner | 谁响应 |
| 处理动作 | 先看什么，怎么处理 |
| 降级方式 | 如何临时保住业务 |
| 回滚方式 | 回退到哪个版本或流程 |
| 复盘要求 | 事故后要留下什么记录 |

## 示例：客服 AI 建议回复

| 字段 | 内容 |
| --- | --- |
| 业务承诺 | 缩短客服退款咨询响应时间，并保持政策口径一致 |
| SLI 指标 | 建议生成成功率、延迟、评测通过率、人工采纳率 |
| SLO 目标 | 工作时间成功率 99%，95% 请求 3 秒内返回，评测通过率不低于 90% |
| 告警条件 | 失败率超过 3%，或评测通过率低于 85% |
| Owner | 客服运营 + 平台值班 |
| 降级方式 | 暂停 AI 建议，切回人工知识库 |
| 回滚方式 | 回退到上一版 Prompt 和知识库 |

## AI 项目的特殊 SLO

AI 项目不能只看可用性，还要看：

- 输出质量。
- 评测通过率。
- 失败样本类型。
- 人工接管率。
- 成本。
- 高风险场景转人工率。

## 使用提醒

如果一个 SLO 没有 Owner，它就只是一个指标。

SLO 定义卡必须和告警、值班、运行手册、客户接管清单一起使用，才真正有意义。

## SLI、SLO 和告警不要混在一起

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| SLI | 观测什么 | 建议生成成功率、延迟、采纳率 |
| SLO | 目标是多少 | 工作时间成功率 99%，95% 请求 3 秒内返回 |
| 告警 | 什么时候叫人处理 | 失败率 10 分钟内超过 3% |

很多项目只写了指标，没有写目标和告警，所以系统坏了也没人知道该不该处理。

## AI 场景的 SLO 示例

| 类型 | SLI | SLO |
| --- | --- | --- |
| 可用性 | 请求成功率 | 工作时间不低于 99% |
| 性能 | P95 延迟 | 3 秒内返回 |
| 质量 | 评测集通过率 | 不低于 90% |
| 采用 | 人工采纳率 | 稳定高于 60% |
| 风险 | 高风险转人工率 | 100% 转人工 |
| 成本 | 单次请求成本 | 不超过预算阈值 |

## 常见错误

- 只写系统可用性，不写 AI 输出质量。
- 只写模型准确率，不写业务采用。
- 告警条件太敏感，导致没人理会。
- 告警有了，但没有处理动作和 Owner。
- 没有降级方案，事故时只能临时救火。

## 合格标准

一张 SLO 定义卡合格，至少要能回答：

1. 用户期待系统稳定提供什么能力？
2. 用哪些 SLI 观测这个能力？
3. 什么阈值算违反承诺？
4. 谁响应告警？
5. 如何降级或回滚？

## 可以带走的判断

没有 Owner、告警和降级动作的 SLO，只是一组漂亮指标，不是生产承诺。
