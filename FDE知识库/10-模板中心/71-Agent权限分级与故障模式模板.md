# Agent 权限分级与故障模式模板

Agent 生产化最重要的不是让它能做更多事，而是知道它被允许做什么，以及做错了怎么办。

这个模板用于记录 Agent 的工具权限、人工确认点、失败模式和应对方式。

> **Agent 能做什么不重要，重要的是它在什么条件下被允许做。**

## 一句话定义

Agent 权限分级与故障模式模板，是一张用于管理 Agent 工具权限、人工确认、审计要求、故障模式和降级策略的生产控制表。

## 工具权限分级

| 等级 | 含义 | 示例 | 是否需要人工确认 |
| --- | --- | --- | --- |
| L1 只读 | 只能查询，不改变状态 | 查询订单、读取知识库 | 否 |
| L2 建议 | 生成建议，但不执行 | 生成回复、生成工单草稿 | 视场景 |
| L3 审批后写入 | 人确认后写入业务系统 | 更新 CRM、创建工单 | 是 |
| L4 自动写入 | 低风险自动执行 | 自动打标签、发送低风险通知 | 否，但要可回滚 |

## 故障模式表

| 故障模式 | 表现 | 风险等级 | 检测方式 | 处理动作 | Owner |
| --- | --- | --- | --- | --- | --- |
| 目标误解 | Agent 执行了错误任务 | P1 | Trace 回放、用户反馈 | 暂停自动执行，修正任务模板 | FDE |
| 工具误选 | 调错接口 | P1 | 工具调用日志 | 降级到人工确认 | 平台 |

## 上线前检查

- 每个工具是否有权限等级？
- L3/L4 工具是否有审计？
- 是否设置最大步数和成本限制？
- 是否有人工接管条件？
- 是否能回放每次执行？
- 是否有 P0/P1 故障处理流程？

## 使用提醒

Agent 权限表不要只由技术团队填写。业务 Owner、安全、平台和 FDE 都应该参与，因为权限不是技术问题，而是业务责任问题。

尤其是 L3 和 L4 权限，讨论的不是“技术上能不能写入”，而是“业务上谁承担写入后的责任”。

## 放权前的判断

Agent 权限不要一次放到最大。每次从 L1 升到 L2、L2 升到 L3、L3 升到 L4，都要有证据。

| 升级 | 必要证据 |
| --- | --- |
| L1 到 L2 | 用户确认建议有价值，输出可解释 |
| L2 到 L3 | 人工确认流程稳定，错误率可接受 |
| L3 到 L4 | 场景低风险，回滚可靠，审计完整 |

如果没有升级证据，就不要把“能自动做”当成“应该自动做”。

## 合格标准

一个 Agent 上线前，至少要说清楚：

- 每个工具是什么权限等级。
- 哪些动作必须人工确认。
- 最大执行步数和成本上限是多少。
- 哪些故障会触发自动停用。
- 审计日志谁能看。
- 失败样本如何进入回归测试。

## 可以带走的判断

Agent 生产化的核心不是自动化程度，而是权限、审计、回滚和人工接管是否同时成立。
