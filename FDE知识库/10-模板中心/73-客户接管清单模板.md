# 客户接管清单模板

客户接管清单用于验证客户组织是否能持续运行、复查、调整和演进系统。

它不是培训签到表，也不是功能验收表。它要证明：FDE 团队离开后，客户仍然能接住系统。

> **接管不是客户会用系统，而是客户能解释、运营、复查和应急。**

## 一句话定义

客户接管清单是一张用于验证客户是否具备持续运行、监控、调整、回滚和演进系统能力的交接表。

## 使用提醒

接管不是一次会议。

真正的接管要经过解释、操作、演练和复查。如果客户只能正常使用，但不能处理异常，那还没有完成接管。

## 接管完成标准

客户接管不是“培训完成”，而是客户能独立完成四件事：

| 能力 | 判断方式 |
| --- | --- |
| 解释 | 能说清系统解决什么问题、不能解决什么问题 |
| 操作 | 能完成日常配置、查看指标、处理反馈 |
| 复查 | 能回放失败样本，判断质量是否下降 |
| 应急 | 能处理告警、降级、回滚或升级问题 |

如果客户只能使用系统，但不能解释和应急，FDE 还没有真正离场。

## 交接包目录

| 文件 | 用途 |
| --- | --- |
| 项目说明 | 场景、用户、范围和不适用边界 |
| AI 资产清单 | Prompt、知识库、模型、工具、评测集版本 |
| 运行手册 | 日常操作、监控、告警、处理动作 |
| 回滚手册 | 出问题时如何降级或回退 |
| 评测说明 | 如何回放样本，如何新增失败样本 |
| 开放风险表 | 仍未关闭的风险和后续计划 |

## 常见假接管

- 只做了功能培训，没有做异常演练。
- 只有业务会用，IT 不知道怎么运维。
- 只有 FDE 会改 Prompt 和知识库。
- 告警发出来后没人知道先看哪里。
- 客户没有复查失败样本的节奏。

## 可以带走的判断

FDE 真正离场的标志，不是项目验收，而是客户组织已经能独立处理正常运行和异常情况。
